In this tutorial you'll build a shielded pool: anyone deposits a fixed amount, and later
withdraws it to a new address. Onchain, an observer sees a deposit and, separately, a
withdrawal, with nothing to say which deposit it came from.

The pool is two ideas you already have, combined: [03](/docs/tutorials/03-token-claim)'s **Merkle
tree**, with [02](/docs/tutorials/02-zkyc)'s **salted commitments** as its leaves. A deposit appends
a commitment to secrets only the depositor knows; a withdrawal proves it knows the secrets behind
*some* leaf, without saying which, and reveals a **nullifier** so the same deposit can't be
withdrawn twice. [Range proofs](/docs/learn-zk/range-proofs) play only a supporting role here,
because every deposit is the same amount. By the end you'll have:

- a **shared crate**, `pool`: the Merkle tree of deposits, as plain Rust a wallet also runs;
- a **deposit circuit**, which proves a new tree root is the old tree with one leaf appended;
- a **withdraw circuit**, which proves you own *some* leaf, and reveals its nullifier;
- a **Pinocchio program** that holds the SOL, keeps recent roots and spent nullifiers, and never
  hashes the tree;
- an **end-to-end test**: two deposits, then a withdrawal relayed to a fresh address, once.

## How it works

In [03](/docs/tutorials/03-token-claim) a claimant proved their address was a leaf of a list,
with the Merkle path as a private input. The claimant was public, though: the program paid the
signer. A shielded pool hides who is paid, with two new pieces.

A deposit is a secret **note**: two random field elements, `nullifier` and `secret`. The depositor
keeps it, and the pool appends its **commitment**, Poseidon2's `commit` of both, as the next leaf
of a Merkle tree. It's 02's salted commitment with nothing left to hide but randomness: both fields are
random, so no one can guess a note from its commitment. To withdraw, the owner proves two things without saying which leaf is theirs:

1. their commitment is a leaf of a tree whose root the program knows (03's Merkle path);
2. a value only the note's owner can compute, its **nullifier hash**, is what they say it is.

The program records each nullifier hash it pays out, so a note can't be withdrawn twice. 03 kept
a receipt per claimant; here the program never learns who withdraws, so it keys the receipt on
the nullifier hash instead. Since the proof hides the leaf, the withdrawal could have come from any
deposit in the tree.

**The chain never hashes.** In 03 the distributor published a fixed root. Here the tree grows with
every deposit, and if the program hashed the new leaf in itself, its hash and the circuit's
would have to agree to the byte, or the roots would never match. So the program doesn't hash the
tree at all. A deposit comes with a proof that the new root is the program's tree with one more
leaf, and the program stores that root. Every tree hash lives in the circuits, and they agree with
the program by construction.

For the gadgets underneath, see [Commitments & Merkle trees](/docs/gadgets/commitments) and
[Hashes](/docs/gadgets/hashes).

### Write the tree

Replace `circuits/pool/Cargo.toml` with:


The tree is [03's](/docs/tutorials/03-token-claim), `xark-merkle`'s Poseidon2 tree: a `Path` with
the same `first`, `next` and `update`, kept by the wallet as the **path of the next free leaf**.
03's `list_root` is `tree_root` here: that path's root over the still-empty slot. What's new is
`append`, for the deposit circuit: `xark-merkle`'s `merkle_append`, which proves the slot is empty
under one root and returns the root with a leaf written there. The empty subtrees `next` needs come
from `xark_merkle::tree`, which builds the whole tree on the host. Replace
`circuits/pool/src/lib.rs` with:

```rust title="circuits/pool/src/lib.rs"
//! What both circuits share: a path into the Merkle tree of notes.
use xark::prelude::*;
use xark_merkle::poseidon2::{merkle_append, merkle_root};
#[cfg(not(xark))]
use xark_merkle::tree::{self, Tree};
#[cfg(not(xark))]
use xark_poseidon2::hash2;

/// Tree height: 2^20 notes.
pub const H: usize = 20;

/// The empty leaf, ASCII `xarkzero`: no note commitment is this value, so an
/// empty slot can't be spent.
pub const ZERO_LEAF: u64 = 0x7861_726b_7a65_726f;

/// The empty tree, as `xark_merkle::tree` builds it on the host.
#[cfg(not(xark))]
pub fn tree() -> Tree<H> {
    Tree::poseidon2(Field::from(ZERO_LEAF))
}

/// A leaf's authentication path: its index, and its sibling at each height.
#[input]
pub struct Path {
    pub index: u32,
    pub siblings: [Field; 20],
}

#[input]
impl Path {
    /// The first leaf's path, in the empty tree.
    #[cfg(not(xark))]
    pub fn first() -> Path {
        tree().path(0).into()
    }

    /// The root of the tree with `leaf` at this path.
    pub fn root(&self, leaf: Field) -> Field {
        merkle_root(leaf, self.siblings, bits(self.index))
    }

    /// For the next free leaf's path, the tree's root: the slot is still empty.
    pub fn tree_root(&self) -> Field {
        self.root(Field::from(ZERO_LEAF))
    }

    /// The next free leaf's path, once `leaf` is appended at this one.
    #[cfg(not(xark))]
    pub fn next(self, leaf: Field) -> Path {
        assert!((self.index as usize) < (1 << H) - 1, "the tree is full");
        let index = self.index + 1;
        let empty = tree();
        let mut siblings = self.siblings;
        let mut node = leaf;
        for (i, sibling) in siblings.iter_mut().enumerate() {
            let (mine, next) = (self.index >> i, index >> i);
            let old = *sibling;
            if next != mine {
                // A new subtree: its left sibling is this leaf's, its right is empty.
                *sibling = if next & 1 == 1 { node } else { empty.empty_subtrees()[i] };
            }
            node = node_of(mine, node, old);
        }
        Path { index, siblings }
    }

    /// This path once `leaf` lands at `later`, a later leaf's path.
    #[cfg(not(xark))]
    pub fn update(self, later: Path, leaf: Field) -> Path {
        assert!(later.index > self.index, "`later` must be a later leaf's path");
        let mut siblings = self.siblings;
        let mut node = leaf;
        for (i, (sibling, beside)) in siblings.iter_mut().zip(later.siblings).enumerate() {
            let at = later.index >> i;
            if at == self.index >> i ^ 1 {
                *sibling = node;
            }
            node = node_of(at, node, beside);
        }
        Path { index: self.index, siblings }
    }
}

impl Path {
    /// In a circuit: this path's slot holds the empty leaf in the tree rooted at
    /// `old_root`, and the result is that root with `leaf` written there.
    pub fn append(&self, old_root: Field, leaf: Field) -> Field {
        merkle_append(old_root, Field::from(ZERO_LEAF), leaf, self.siblings, bits(self.index))
    }
}

/// A path out of `tree()`, as the circuits take it.
#[cfg(not(xark))]
impl From<tree::Path<H>> for Path {
    fn from(path: tree::Path<H>) -> Path {
        Path { index: path.index as u32, siblings: path.siblings }
    }
}

/// `index` as the tree's `H` bits, least significant first. In a circuit this
/// binds `index` below 2^20.
fn bits(index: u32) -> [Field; H] {
    Field::from(index).to_bits::<H>()
}

/// The parent of `node`, at position `at` in its level, and its `sibling`.
#[cfg(not(xark))]
fn node_of(at: u32, node: Field, sibling: Field) -> Field {
    if at & 1 == 0 { hash2(node, sibling) } else { hash2(sibling, node) }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn paths_agree_with_the_tree() {
        let leaves: Vec<Field> = (1..=11u64).map(Field::from).collect();
        let mut tree = tree();
        let mut tip = Path::first();
        let mut paths: Vec<Path> = Vec::new();
        for &leaf in &leaves {
            assert_eq!(tip.tree_root(), tree.root());
            paths = paths.into_iter().map(|p| p.update(tip, leaf)).collect();
            paths.push(tip);
            tip = tip.next(leaf);
            tree.push(leaf);
            // Every path the wallet keeps is the tree's, and so is the tip.
            for (i, path) in paths.iter().chain([&tip]).enumerate() {
                let want = tree.path(i);
                assert_eq!((path.index as usize, path.siblings), (want.index, want.siblings));
            }
        }
    }
}
```

As in 03, `root` is what a circuit calls to prove membership, and `append` what it calls to grow
the tree; `first`, `next` and `update` are host-only (`#[cfg(not(xark))]`). `#[input] impl` puts
them in the TypeScript clients; `append`, in a plain `impl`, stays out, since only a circuit calls
it. The nodes are Poseidon2's 2-to-1 `hash2`, and the notes will be Poseidon2's `commit` and
`nullifier`, each its sponge in a domain of its own, so a node can't pass for a note. The crate is
its own: both circuits depend on it, and so does [06](/docs/tutorials/06-shielded-transfer). The
test checks every path the wallet keeps against `xark_merkle::tree`'s, which a host holding every
note would use instead. Run it:

```console

...

test result: ok. 1 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.20s
```

### Write the deposit circuit

Add `pool` to the deposit crate:

```sh
cargo add -p shielded-pool-deposit --path circuits/pool
```

A deposit proves one statement, its public `Append`: the program's root and next index, the new
leaf, and the root once the leaf is appended. Replace `circuits/shielded-pool-deposit/src/lib.rs`
with:

```rust title="circuits/shielded-pool-deposit/src/lib.rs"
use pool::Path;
use xark::prelude::*;

/// What the program checks a deposit against: its tree's root and next index,
/// the new leaf, and the root once the leaf is appended. The public inputs, in
/// this order.
#[input]
pub struct Append {
    pub old_root: Field,
    pub new_root: Field,
    pub leaf: Field,
    pub index: u32,
}

#[input]
impl Append {
    /// `leaf` appended at `path`, the next free leaf's path: what the circuit
    /// proves, computed on the host.
    #[cfg(not(xark))]
    pub fn of(path: Path, leaf: Field) -> Append {
        Append {
            old_root: path.tree_root(),
            new_root: path.root(leaf),
            leaf,
            index: path.index,
        }
    }
}

#[circuit]
pub fn shielded_pool_deposit(path: Private<Path>, append: Public<Append>) {
    require(path.index == append.index);
    require_eq(path.append(append.old_root, append.leaf), append.new_root);
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn appends_to_the_tree() {
        let tip = Path::first().next(Field::from(7u64));
        let append = Append::of(tip, Field::from(8u64));
        shielded_pool_deposit(tip, append).unwrap();
        // Another index, the empty tree's root, or the first slot again, over the
        // leaf already there: each is refused.
        assert!(shielded_pool_deposit(tip, Append { index: 2, ..append }).is_err());
        let empty = Path::first().tree_root();
        assert!(shielded_pool_deposit(tip, Append { old_root: empty, ..append }).is_err());
        assert!(shielded_pool_deposit(Path::first(), Append { index: 0, ..append }).is_err());
    }
}
```

The circuit is two lines: the private path is at the program's index, and `append` from the
program's `old_root` gives the claimed `new_root`. `merkle_append` hashes the one path twice: with
the empty leaf it must reach `old_root`, and with the new leaf it gives the root to return. Only the
tree's true siblings hash up to the program's root, so the same siblings give the true `new_root`.
The depositor can't slip a different tree in, or write over a leaf that's already there.
`Append::of` is the same statement computed on the host, for the wallet and the tests.

### Write the withdraw circuit

The withdraw crate also hashes notes, with Poseidon2's `commit` and `nullifier`:

```sh
cargo add -p shielded-pool-withdraw xark-poseidon2@0.4
cargo add -p shielded-pool-withdraw --path circuits/pool
```

Replace `circuits/shielded-pool-withdraw/src/lib.rs` with:

```rust title="circuits/shielded-pool-withdraw/src/lib.rs"
use pool::Path;
use xark::prelude::*;
use xark_poseidon2::{commit, nullifier};

/// A deposit's secret: whoever knows it can withdraw the deposit, once.
#[input]
pub struct Note {
    pub nullifier: Field,
    pub secret: Field,
}

#[input]
impl Note {
    /// The leaf a deposit appends: it hides both secrets.
    pub fn commitment(&self) -> Field {
        commit(self.to_fields())
    }

    /// What a withdrawal reveals: the same every time for this note, and
    /// unlinkable to its commitment without the secret.
    pub fn nullifier_hash(&self) -> Field {
        nullifier([self.nullifier])
    }
}

/// What the program checks a withdrawal against: the public inputs, in this order.
#[input]
pub struct Withdrawal {
    pub root: Field,
    pub nullifier_hash: Field,
    pub recipient: Address,
    pub relayer: Address,
    pub fee: u64,
}

#[input]
impl Withdrawal {
    /// Withdrawing `note`, at `path`, to `recipient`, paying `fee` to `relayer`.
    pub fn of(note: Note, path: Path, recipient: Address, relayer: Address, fee: u64) -> Withdrawal {
        Withdrawal {
            root: path.root(note.commitment()),
            nullifier_hash: note.nullifier_hash(),
            recipient,
            relayer,
            fee,
        }
    }
}

#[circuit]
pub fn shielded_pool_withdraw(note: Private<Note>, path: Private<Path>, withdrawal: Public<Withdrawal>) {
    // The note is in the tree, and this is its nullifier hash.
    require_eq(path.root(note.commitment()), withdrawal.root);
    require_eq(note.nullifier_hash(), withdrawal.nullifier_hash);
    // Nothing else uses the addresses, so bind them: the proof pays only them.
    bind(withdrawal.recipient);
    bind(withdrawal.relayer);
}

#[cfg(test)]
mod tests {
    use super::*;

    fn note(n: u64) -> Note {
        Note { nullifier: Field::from(n), secret: Field::from(n + 1000) }
    }

    #[test]
    fn withdraws_a_note_in_the_tree() {
        let (mine, theirs) = (note(1), note(2));
        // I deposit, then they do: my path changes with their deposit.
        let path = Path::first();
        let tip = path.next(mine.commitment());
        let path = path.update(tip, theirs.commitment());
        let root = tip.next(theirs.commitment()).tree_root();

        let ok = Withdrawal::of(mine, path, [1; 32].into(), [2; 32].into(), 5);
        assert_eq!(ok.root, root);
        shielded_pool_withdraw(mine, path, ok).unwrap();
        // Their note at my path, or a root my note isn't in: refused.
        let theirs_here = Withdrawal { nullifier_hash: theirs.nullifier_hash(), ..ok };
        assert!(shielded_pool_withdraw(theirs, path, theirs_here).is_err());
        let stale = Withdrawal { root: tip.tree_root(), ..ok };
        assert!(shielded_pool_withdraw(mine, path, stale).is_err());
    }
}
```

`commit` and `nullifier` are the Poseidon2 sponge, each in a domain of its own, so a commitment is
never a nullifier hash or a tree node. `recipient`, `relayer` and `fee` are public inputs the
program fills in from the transaction, so whoever submits the proof can't redirect the payout. The
two addresses are `Address`es, xark's Solana address, as the holder was in
[02](/docs/tutorials/02-zkyc), and are only bound. `fee` is a `u64`, and its range check
already uses it.

That range check is one of the pool's two [range proofs](/docs/learn-zk/range-proofs), and both
play a supporting role. `fee` is checked to 64 bits as it's read, and the program then checks it's
at most the denomination before paying it out. The leaf index in `Path` is a `u32`, and
`to_bits::<H>()` in `Path::root` bounds it below 2^20 while splitting out the bits that steer the
path. Amounts need no range proof at all: every note in a pool is the same denomination.

```ts title="tests/shielded-pool.test.ts"
import { beforeAll, expect, test } from "vitest";
import { Append, Path, ShieldedPoolDeposit, type ShieldedPoolDepositProver } from "../clients/shielded-pool-deposit/ts/shielded_pool_deposit";
import { Field, Note, ShieldedPoolWithdraw, Withdrawal, type ShieldedPoolWithdrawProver } from "../clients/shielded-pool-withdraw/ts/shielded_pool_withdraw";

let deposits: ShieldedPoolDepositProver;
let withdrawals: ShieldedPoolWithdrawProver;
beforeAll(async () => {
  deposits = await ShieldedPoolDeposit.prover(circuit("shielded-pool-deposit"), { digest: ShieldedPoolDeposit.digest });
  withdrawals = await ShieldedPoolWithdraw.prover(circuit("shielded-pool-withdraw"), { digest: ShieldedPoolWithdraw.digest });
});

/** A fresh note: two random field elements, kept secret by the depositor. */
const newNote = (): Note => ({
  nullifier: new Field(crypto.getRandomValues(new Uint8Array(31))),
  secret: new Field(crypto.getRandomValues(new Uint8Array(31))),
});

test("a wallet keeps its path as others deposit", () => {
  const [mine, theirs] = [newNote(), newNote()];
  let tip = Path.first(); // the empty tree's next free leaf
  let path = tip; // my note lands here
  tip = tip.next(Note.commitment(mine));
  // They deposit after me: my path changes beside theirs.
  path = path.update(tip, Note.commitment(theirs));
  tip = tip.next(Note.commitment(theirs));

  const zero = new Uint8Array(32);
  const withdrawal = Withdrawal.of(mine, path, zero, zero, 0);
  expect(withdrawal.root).toEqual(tip.treeRoot());
  withdrawals.prove({ note: mine, path, withdrawal });

  // A note that isn't in the tree has no proof.
  const stranger = newNote();
  const theirClaim = { ...Withdrawal.of(stranger, path, zero, zero, 0), root: tip.treeRoot() };
  expect(() => withdrawals.prove({ note: stranger, path, withdrawal: theirClaim })).toThrow(
    /path\.root\(note\.commitment\(\)\)/,
  );
}, 60_000);
```

### Start the program

The program is Pinocchio, as in 01 to 03, and has three instructions:

- `initialize(denomination)` creates a pool for one amount, at a PDA seeded by that amount. One
  program serves 0.1, 1 or 10 SOL pools side by side, and every note in a pool is worth the same.
- `deposit(commitment, new_root, proof)` checks the proof against its own root and next index,
  takes the denomination, and stores `new_root`.
- `withdraw(proof, root, nullifier_hash, fee)` checks that `root` is one of its 16 most recent
  roots, checks the proof against the recipient and relayer accounts, creates a PDA for the
  nullifier hash and pays out. A second withdrawal of the same note finds that PDA and fails.

It's longer than 03's, so you'll write it in pieces, in the usual Pinocchio layout:

```text
programs/shielded-pool/src/
├── lib.rs                  the entrypoint
├── state.rs                the pool's account and the nullifier's
├── helpers.rs              the account checks the instructions share
├── instructions/
│   ├── mod.rs
│   ├── initialize.rs
│   ├── deposit.rs
│   └── withdraw.rs
└── errors.rs               the program's own errors
```

The first byte of the instruction data is a discriminator, which instruction it is: `0`, `1` or
`2`. Each instruction's file declares its own, and the entrypoint hands the rest of the data and
the accounts to that instruction. Replace `programs/shielded-pool/src/lib.rs` with:

```rust title="programs/shielded-pool/src/lib.rs"
#![cfg_attr(not(test), no_std)]

use pinocchio::{AccountView, Address, ProgramResult, error::ProgramError, program_entrypoint};

mod errors;
mod helpers;
mod instructions;
mod state;

pub use errors::*;
pub use instructions::*;

// Fg6PaFpoGXkYsidMpWTK6W2BeZ7FEfcYkg476zPFsLnS
pub const ID: Address = Address::new_from_array([
    0xda, 0x07, 0x5c, 0xb2, 0xff, 0x5e, 0xc6, 0x81, 0x76, 0x13, 0xde, 0x53, 0x0b, 0x69, 0x2a, 0x87,
    0x35, 0x47, 0x77, 0x69, 0xda, 0x47, 0x43, 0x0c, 0xbd, 0x81, 0x54, 0x33, 0x5c, 0x4a, 0x83, 0x27,
]);

program_entrypoint!(process_instruction);
#[cfg(not(test))]
pinocchio::nostd_panic_handler!();
#[cfg(not(test))]
pinocchio::no_allocator!();

fn process_instruction(
    _program_id: &Address,
    accounts: &mut [AccountView],
    instruction_data: &[u8],
) -> ProgramResult {
    let result = dispatch(accounts, instruction_data);
    // The program's own errors log their names, which the test matches.
    if let Err(error @ ProgramError::Custom(_)) = &result {
        helpers::log(error.to_str::<ShieldedPoolError>());
    }
    result
}

fn dispatch(accounts: &mut [AccountView], instruction_data: &[u8]) -> ProgramResult {
    match instruction_data.split_first() {
        Some((Initialize::DISCRIMINATOR, data)) => {
            Initialize::try_from((data, accounts))?.process()
        }
        Some((Deposit::DISCRIMINATOR, data)) => Deposit::try_from((data, accounts))?.process(),
        Some((Withdraw::DISCRIMINATOR, data)) => Withdraw::try_from((data, accounts))?.process(),
        _ => Err(ProgramError::InvalidInstructionData),
    }
}
```

`ID` is the program's address. The program checks its accounts against it, so it must be the
address the program is deployed at; the test at the end deploys it there. The errors it logs are
the ones you'll write last. The program is `no_std` except in its own tests, which `xark test`
runs on the host.
</Step>

<Step>
### Lay out the accounts

The program owns two kinds of account, each at a PDA:

| PDA | Seeds | Size |
|---|---|--:|
| `pool` | `["pool", denomination as u64 LE]` | 536 |
| `nullifier` | `["nullifier", denomination as u64 LE, nullifier_hash]` | 1 |

Each starts with a tag byte, so one kind can't be passed off as the other. Create
`programs/shielded-pool/src/state.rs`:

```rust title="programs/shielded-pool/src/state.rs"
use pinocchio::{AccountView, Address, ProgramResult, error::ProgramError};

use crate::helpers::writable;

pub const TREE_HEIGHT: u32 = 20;
pub const ROOT_HISTORY_SIZE: usize = 16;
pub const POOL_SEED: &[u8] = b"pool";
pub const NULLIFIER_SEED: &[u8] = b"nullifier";

// The empty tree's root, little-endian: `Path.first().treeRoot()`. Fixed here so
// a pool can't be seeded with another tree.
pub const EMPTY_ROOT: [u8; 32] = [
    251, 142, 67, 247, 199, 111, 241, 124, 245, 96, 180, 214, 179, 51, 248, 149, 20, 177, 173, 83,
    193, 126, 124, 38, 168, 0, 139, 11, 55, 225, 46, 3,
];

/// A pool's account, 536 bytes: tag, bump, 6 reserved bytes, then
/// `denomination` (u64 LE), `next_index` and `current_root_index` (u32 LE), and
/// a ring of the 16 most recent roots.
#[repr(C)]
pub struct Pool {
    pub tag: u8,
    pub bump: u8,
    reserved: [u8; 6],
    pub denomination: [u8; 8],
    next_index: [u8; 4],
    current_root_index: [u8; 4],
    roots: [[u8; 32]; ROOT_HISTORY_SIZE],
}

const _: () = assert!(Pool::LEN == 536);

impl Pool {
    pub const LEN: usize = size_of::<Self>();
    pub const TAG: u8 = 1;

    /// The pool `data` holds, if it is a pool's size and tag.
    pub fn load(data: &[u8]) -> Result<&Self, ProgramError> {
        if data.len() != Self::LEN || data[0] != Self::TAG {
            return Err(ProgramError::InvalidAccountData);
        }
        // SAFETY: `Pool` is all byte arrays (alignment 1, any bit pattern valid),
        // and `data` is exactly its size.
        Ok(unsafe { &*data.as_ptr().cast::<Self>() })
    }

    /// As `load`, to write.
    pub fn load_mut(data: &mut [u8]) -> Result<&mut Self, ProgramError> {
        if data.len() != Self::LEN || data[0] != Self::TAG {
            return Err(ProgramError::InvalidAccountData);
        }
        // SAFETY: as above.
        Ok(unsafe { &mut *data.as_mut_ptr().cast::<Self>() })
    }

    /// Write a new pool into a freshly created account, which is zeroed: the
    /// ring's other slots are empty.
    pub fn init(data: &mut [u8], denomination: [u8; 8], bump: u8) -> ProgramResult {
        if data.len() != Self::LEN {
            return Err(ProgramError::InvalidAccountData);
        }
        // SAFETY: as above.
        let pool = unsafe { &mut *data.as_mut_ptr().cast::<Self>() };
        pool.tag = Self::TAG;
        pool.bump = bump;
        pool.denomination = denomination;
        pool.roots[0] = EMPTY_ROOT;
        Ok(())
    }

    pub fn denomination(&self) -> u64 {
        u64::from_le_bytes(self.denomination)
    }

    pub fn next_index(&self) -> u32 {
        u32::from_le_bytes(self.next_index)
    }

    pub fn current_root(&self) -> &[u8; 32] {
        let i = u32::from_le_bytes(self.current_root_index) as usize % ROOT_HISTORY_SIZE;
        &self.roots[i]
    }

    /// Remember `root` as the newest in the ring, and advance the tree. The caller
    /// has checked the tree isn't full.
    pub fn push_root(&mut self, root: &[u8; 32]) {
        let i = (u32::from_le_bytes(self.current_root_index) as usize + 1) % ROOT_HISTORY_SIZE;
        self.current_root_index = (i as u32).to_le_bytes();
        self.roots[i] = *root;
        self.next_index = (self.next_index() + 1).to_le_bytes();
    }

    /// One of the recent roots. The ring's unused slots are zero; no root is.
    pub fn knows_root(&self, root: &[u8; 32]) -> bool {
        root != &[0; 32] && self.roots.contains(root)
    }
}

/// A spent nullifier's account: one byte, its tag. That it exists is what counts.
pub struct Nullifier;

impl Nullifier {
    pub const LEN: usize = 1;
    pub const TAG: u8 = 2;
}
```

A pool is plain bytes: every field is a byte array, read little-endian, so the account's data is
the struct, at any address, and `load` reads it in place, with no parsing and no copying. The 6
reserved bytes put `denomination` at offset 8, and the roots start at 24, which is where the test
will read the empty root. The ring keeps 16 roots, so a withdrawal proved against the tree a few
deposits ago still verifies. `EMPTY_ROOT` is the one tree value the program holds itself, and the
test checks it against the circuit's `Path.first().treeRoot()`.
</Step>

<Step>
### Check every account

Nothing checks an account for a Pinocchio program: the runtime hands it the accounts the
transaction names, and anyone can name any account. So each check is written out, once, and each
instruction's accounts struct calls the ones it needs. Create
`programs/shielded-pool/src/helpers.rs`:

```rust title="programs/shielded-pool/src/helpers.rs"
use pinocchio::{AccountView, ProgramResult, error::ProgramError};

/// An account the program writes to.
pub fn writable(account: &AccountView) -> ProgramResult {
    if !account.is_writable() {
        return Err(ProgramError::Immutable);
    }
    Ok(())
}

/// A payer: a signer, writable.
pub fn writable_signer(account: &AccountView) -> ProgramResult {
    if !account.is_signer() {
        return Err(ProgramError::MissingRequiredSignature);
    }
    writable(account)
}

/// The system program, which creates the accounts and moves the deposits.
pub fn system_program(account: &AccountView) -> ProgramResult {
    if account.address() != &pinocchio_system::ID {
        return Err(ProgramError::IncorrectProgramId);
    }
    Ok(())
}

/// An account about to be created: owned by the system program, with no data.
/// It may already hold lamports, which anyone can send it; creation tops them
/// up to rent exemption.
pub fn is_uninitialized(account: &AccountView) -> bool {
    account.owned_by(&pinocchio_system::ID) && account.is_data_empty()
}
```

The pool's own check reads the pool, so it goes with it. Append to `programs/shielded-pool/src/state.rs`:

```rust title="programs/shielded-pool/src/state.rs"
impl Pool {
    /// A pool account: writable, owned by this program, a pool's size and tag, at
    /// the address its own denomination and stored bump derive.
    pub fn check(account: &AccountView) -> ProgramResult {
        writable(account)?;
        if !account.owned_by(&crate::ID) {
            return Err(ProgramError::InvalidAccountOwner);
        }
        let data = account.try_borrow()?;
        let pool = Self::load(&data)?;
        let address = Address::derive_address(
            &[POOL_SEED, &pool.denomination],
            Some(pool.bump),
            &crate::ID,
        );
        if account.address() != &address {
            return Err(ProgramError::InvalidSeeds);
        }
        Ok(())
    }
}
```

What each one prevents:

- **`writable`**: a read-only account can't be changed, and the runtime would only fail the
  transaction after the program ran; the check fails it up front, with `Immutable`.
- **`writable_signer`**: the depositor's lamports, and the rent for a new account, move only with
  their owner's signature, so no one can spend someone else's SOL into the pool.
- **`system_program`**: the CPIs call the system program by its address, and the runtime would
  refuse them with that account missing; the check names the problem first, with
  `IncorrectProgramId`.
- **`is_uninitialized`**: an account about to be created doesn't exist yet, so `initialize` can't
  reset a live pool's roots, and a nullifier that exists means its note is spent. It allows
  lamports already at the address, which anyone can send, so no one can block a withdrawal by
  funding its nullifier's address first.
- **`Pool::check`**: only this program can write an account it owns, so the owner check makes the
  roots and the index the program's own, not ones someone wrote to look like them. The size and
  tag tell a pool from a nullifier, and the address ties it to its own denomination. The bump is
  the one the pool stored when it was created, so the check is one hash, not a search.
</Step>

### Create a pool

Each instruction is three structs, as in [02](/docs/tutorials/02-zkyc): its accounts, checked as
they're taken; its instruction data, checked for length; and the instruction, which holds both and
whose `process` does the work. Replace `programs/shielded-pool/src/instructions/mod.rs` with:

Then `programs/shielded-pool/src/instructions/initialize.rs`:

```rust title="programs/shielded-pool/src/instructions/initialize.rs"
use pinocchio::{
    AccountView, Address, ProgramResult,
    cpi::{Seed, Signer},
    error::ProgramError,
};

use crate::{
    helpers::{is_uninitialized, system_program, writable, writable_signer},
    state::{POOL_SEED, Pool},
};

/// Accounts: the pool (the PDA, not yet created), the authority (pays the
/// rent), the system program.
pub struct InitializeAccounts<'a> {
    pub pool: &'a mut AccountView,
    pub authority: &'a AccountView,
}

impl<'a> TryFrom<&'a mut [AccountView]> for InitializeAccounts<'a> {
    type Error = ProgramError;

    fn try_from(accounts: &'a mut [AccountView]) -> Result<Self, Self::Error> {
        let [pool, authority, system, ..] = accounts else {
            return Err(ProgramError::NotEnoughAccountKeys);
        };
        writable_signer(authority)?;
        system_program(system)?;
        writable(pool)?;
        Ok(Self { pool, authority })
    }
}

/// Data: denomination (u64 LE).
pub struct InitializeInstructionData {
    pub denomination: [u8; 8],
}

impl TryFrom<&[u8]> for InitializeInstructionData {
    type Error = ProgramError;

    fn try_from(data: &[u8]) -> Result<Self, Self::Error> {
        let denomination = data
            .try_into()
            .map_err(|_| ProgramError::InvalidInstructionData)?;
        Ok(Self { denomination })
    }
}

/// Create the pool for one denomination, with the empty tree's root.
pub struct Initialize<'a> {
    pub accounts: InitializeAccounts<'a>,
    pub data: InitializeInstructionData,
    pub bump: u8,
}

impl<'a> TryFrom<(&'a [u8], &'a mut [AccountView])> for Initialize<'a> {
    type Error = ProgramError;

    fn try_from((data, accounts): (&'a [u8], &'a mut [AccountView])) -> Result<Self, Self::Error> {
        let accounts = InitializeAccounts::try_from(accounts)?;
        let data = InitializeInstructionData::try_from(data)?;
        // One pool per denomination, at the canonical bump.
        let (address, bump) =
            Address::find_program_address(&[POOL_SEED, &data.denomination], &crate::ID);
        if accounts.pool.address() != &address {
            return Err(ProgramError::InvalidSeeds);
        }
        if !is_uninitialized(accounts.pool) {
            return Err(ProgramError::AccountAlreadyInitialized);
        }
        Ok(Self {
            accounts,
            data,
            bump,
        })
    }
}

impl<'a> Initialize<'a> {
    pub const DISCRIMINATOR: &'a u8 = &0;

    pub fn process(&mut self) -> ProgramResult {
        let bump = [self.bump];
        let seeds = [
            Seed::from(POOL_SEED),
            Seed::from(&self.data.denomination),
            Seed::from(&bump),
        ];
        pinocchio_system::create_account_with_minimum_balance_signed(
            self.accounts.pool,
            Pool::LEN,
            &crate::ID,
            self.accounts.authority,
            None,
            &[Signer::from(&seeds)],
        )?;
        let mut data = self.accounts.pool.try_borrow_mut()?;
        Pool::init(&mut data, self.data.denomination, self.bump)
    }
}
```

The checks, and what they prevent:

- **The data is exactly 8 bytes**, the denomination, so a short or long instruction is refused
  before anything reads it.
- **The pool is the denomination's PDA at its canonical bump**, the one `find_program_address`
  returns. Another bump would give another valid address, and so a second pool for the same
  amount; this way there's exactly one. The pool stores the bump, and every later check derives
  the address from it.
- **The pool doesn't exist yet**, so no one can reinitialize a live pool and wipe its roots.

The account is created by a `pinocchio-system` CPI, signed with the pool's seeds, and is zeroed,
so `init` sets only the first root in the ring. Anyone can create a pool; the empty root is a
constant, so no one can seed one with another tree.
</Step>

### Deposit

A deposit logs an event, for wallets to follow the tree by. The log is a helper; append to
`programs/shielded-pool/src/helpers.rs`:

```rust title="programs/shielded-pool/src/helpers.rs"

pub fn log_data(data: &[&[u8]]) {

        pinocchio::syscalls::sol_log_data(data.as_ptr().cast(), data.len() as u64)

    #[cfg(not(any(target_os = "solana", target_arch = "bpf")))]

```

Create `programs/shielded-pool/src/instructions/deposit.rs`:

```rust title="programs/shielded-pool/src/instructions/deposit.rs"
use pinocchio::{AccountView, ProgramResult, error::ProgramError};
use pinocchio_system::instructions::Transfer;
use shielded_pool_deposit_verifier::{Append, Proof, PublicInputs, verify};

use crate::{
    ShieldedPoolError,
    helpers::{log_data, system_program, writable_signer},
    state::{Pool, TREE_HEIGHT},
};

/// Accounts: the pool, the depositor (signs, pays the denomination), the system
/// program.
pub struct DepositAccounts<'a> {
    pub pool: &'a mut AccountView,
    pub depositor: &'a AccountView,
}

impl<'a> TryFrom<&'a mut [AccountView]> for DepositAccounts<'a> {
    type Error = ProgramError;

    fn try_from(accounts: &'a mut [AccountView]) -> Result<Self, Self::Error> {
        let [pool, depositor, system, ..] = accounts else {
            return Err(ProgramError::NotEnoughAccountKeys);
        };
        Pool::check(pool)?;
        writable_signer(depositor)?;
        system_program(system)?;
        Ok(Self { pool, depositor })
    }
}

/// Data: commitment (32) ‖ new_root (32) ‖ proof (256).
pub struct DepositInstructionData<'a> {
    pub commitment: &'a [u8; 32],
    pub new_root: &'a [u8; 32],
    pub proof: &'a [u8; 256],
}

impl<'a> TryFrom<&'a [u8]> for DepositInstructionData<'a> {
    type Error = ProgramError;

    fn try_from(data: &'a [u8]) -> Result<Self, Self::Error> {
        let (commitment, data) = data
            .split_first_chunk()
            .ok_or(ProgramError::InvalidInstructionData)?;
        let (new_root, proof) = data
            .split_first_chunk()
            .ok_or(ProgramError::InvalidInstructionData)?;
        let proof = proof
            .try_into()
            .map_err(|_| ProgramError::InvalidInstructionData)?;
        Ok(Self {
            commitment,
            new_root,
            proof,
        })
    }
}

/// Deposit the denomination and append `commitment`. The proof says `new_root`
/// is the current tree with `commitment` appended.
pub struct Deposit<'a> {
    pub accounts: DepositAccounts<'a>,
    pub data: DepositInstructionData<'a>,
}

impl<'a> TryFrom<(&'a [u8], &'a mut [AccountView])> for Deposit<'a> {
    type Error = ProgramError;

    fn try_from((data, accounts): (&'a [u8], &'a mut [AccountView])) -> Result<Self, Self::Error> {
        let accounts = DepositAccounts::try_from(accounts)?;
        let data = DepositInstructionData::try_from(data)?;
        Ok(Self { accounts, data })
    }
}

impl<'a> Deposit<'a> {
    pub const DISCRIMINATOR: &'a u8 = &1;

    pub fn process(&mut self) -> ProgramResult {
        let (denomination, index) = {
            let mut data = self.accounts.pool.try_borrow_mut()?;
            let pool = Pool::load_mut(&mut data)?;
            let index = pool.next_index();
            if index >= 1 << TREE_HEIGHT {
                return Err(ShieldedPoolError::TreeFull.into());
            }

            // The deposit circuit's public `Append`: the tree as the program has
            // it, and the leaf and root the depositor claims.
            let inputs = PublicInputs {
                append: Append {
                    old_root: *pool.current_root(),
                    new_root: *self.data.new_root,
                    leaf: *self.data.commitment,
                    index,
                },
            };
            if !verify(&Proof::from_le_bytes(self.data.proof), inputs) {
                return Err(ShieldedPoolError::InvalidProof.into());
            }
            pool.push_root(self.data.new_root);
            (pool.denomination(), index)
        };

        Transfer {
            from: self.accounts.depositor,
            to: self.accounts.pool,
            lamports: denomination,
        }
        .invoke()?;

        // What a wallet follows the tree by: the commitment and its leaf index.
        log_data(&[self.data.commitment, &index.to_le_bytes()]);
        Ok(())
    }
}
```

The program builds the deposit circuit's `Append` itself: `old_root` and `index` from its own state,
and only the commitment and the new root from the instruction. `PublicInputs` and `Append` come from
the generated verifier crate, with the circuit's own field names; the crate packs them into field
elements in the circuit's order, so the program never lays out a public input by hand. A proof
holds only for this pool's tree as it is now, so the depositor can't append to an older tree, or
at another index. The other checks:

- **The data is exactly 320 bytes**, so the proof the verifier reads is the 256 bytes sent.
- **The tree isn't full.** A tree of height 20 has 2^20 leaves, and the circuit's index can't
  name another, so the program refuses a deposit it could never let anyone withdraw, with
  `TreeFull`.

Then it stores the new root and pulls the denomination from the depositor with a
`pinocchio-system` transfer, which the depositor's signature authorizes. The `Program data:` log
is how a wallet learns of other deposits, to call `update` on its paths.
</Step>

### Withdraw

Create `programs/shielded-pool/src/instructions/withdraw.rs`:

```rust title="programs/shielded-pool/src/instructions/withdraw.rs"
use pinocchio::{
    AccountView, Address, ProgramResult,
    cpi::{Seed, Signer},
    error::ProgramError,
};
use shielded_pool_withdraw_verifier::{Proof, PublicInputs, Withdrawal, verify};

use crate::{
    ShieldedPoolError,
    helpers::{is_uninitialized, system_program, writable, writable_signer},
    state::{NULLIFIER_SEED, Nullifier, Pool},
};

/// Accounts: the pool, the nullifier (the PDA, not yet created), the recipient,
/// the relayer (signs, pays the rent), the system program.
pub struct WithdrawAccounts<'a> {
    pub pool: &'a mut AccountView,
    pub nullifier: &'a mut AccountView,
    pub recipient: &'a mut AccountView,
    pub relayer: &'a mut AccountView,
}

impl<'a> TryFrom<&'a mut [AccountView]> for WithdrawAccounts<'a> {
    type Error = ProgramError;

    fn try_from(accounts: &'a mut [AccountView]) -> Result<Self, Self::Error> {
        let [pool, nullifier, recipient, relayer, system, ..] = accounts else {
            return Err(ProgramError::NotEnoughAccountKeys);
        };
        Pool::check(pool)?;
        writable_signer(relayer)?;
        system_program(system)?;
        writable(recipient)?;
        writable(nullifier)?;
        // The payout moves the pool's lamports: never to the pool's own accounts.
        if recipient.address() == pool.address() || recipient.address() == nullifier.address() {
            return Err(ProgramError::InvalidArgument);
        }
        Ok(Self {
            pool,
            nullifier,
            recipient,
            relayer,
        })
    }
}

/// Data: proof (256) ‖ root (32) ‖ nullifier_hash (32) ‖ fee (u64 LE).
pub struct WithdrawInstructionData<'a> {
    pub proof: &'a [u8; 256],
    pub root: &'a [u8; 32],
    pub nullifier_hash: &'a [u8; 32],
    pub fee: u64,
}

impl<'a> TryFrom<&'a [u8]> for WithdrawInstructionData<'a> {
    type Error = ProgramError;

    fn try_from(data: &'a [u8]) -> Result<Self, Self::Error> {
        let (proof, data) = data
            .split_first_chunk()
            .ok_or(ProgramError::InvalidInstructionData)?;
        let (root, data) = data
            .split_first_chunk()
            .ok_or(ProgramError::InvalidInstructionData)?;
        let (nullifier_hash, fee) = data
            .split_first_chunk()
            .ok_or(ProgramError::InvalidInstructionData)?;
        let fee = fee
            .try_into()
            .map_err(|_| ProgramError::InvalidInstructionData)?;
        Ok(Self {
            proof,
            root,
            nullifier_hash,
            fee: u64::from_le_bytes(fee),
        })
    }
}

/// Pay the denomination, less `fee`, to `recipient`, and `fee` to the relayer.
/// The `nullifier` account is created here: if it exists, the note is spent.
pub struct Withdraw<'a> {
    pub accounts: WithdrawAccounts<'a>,
    pub data: WithdrawInstructionData<'a>,
    pub denomination: [u8; 8],
    pub nullifier_bump: u8,
}

impl<'a> TryFrom<(&'a [u8], &'a mut [AccountView])> for Withdraw<'a> {
    type Error = ProgramError;

    fn try_from((data, accounts): (&'a [u8], &'a mut [AccountView])) -> Result<Self, Self::Error> {
        let accounts = WithdrawAccounts::try_from(accounts)?;
        let data = WithdrawInstructionData::try_from(data)?;
        // The nullifier's account, per denomination, at its canonical bump: another
        // bump would be another address for the same note, to spend it again at.
        let denomination = Pool::load(&accounts.pool.try_borrow()?)?.denomination;
        let seeds = [NULLIFIER_SEED, &denomination, data.nullifier_hash];
        let (address, nullifier_bump) = Address::find_program_address(&seeds, &crate::ID);
        if accounts.nullifier.address() != &address {
            return Err(ProgramError::InvalidSeeds);
        }
        if !is_uninitialized(accounts.nullifier) {
            return Err(ShieldedPoolError::NullifierSpent.into());
        }
        Ok(Self {
            accounts,
            data,
            denomination,
            nullifier_bump,
        })
    }
}

impl<'a> Withdraw<'a> {
    pub const DISCRIMINATOR: &'a u8 = &2;

    pub fn process(&mut self) -> ProgramResult {
        let denomination = u64::from_le_bytes(self.denomination);
        let fee = self.data.fee;
        if fee > denomination {
            return Err(ShieldedPoolError::FeeTooHigh.into());
        }
        if !Pool::load(&self.accounts.pool.try_borrow()?)?.knows_root(self.data.root) {
            return Err(ShieldedPoolError::UnknownRoot.into());
        }

        // The withdraw circuit's public `Withdrawal`: the recipient and relayer are
        // this transaction's accounts.
        let inputs = PublicInputs {
            withdrawal: Withdrawal {
                root: *self.data.root,
                nullifier_hash: *self.data.nullifier_hash,
                recipient: self.accounts.recipient.address().to_bytes(),
                relayer: self.accounts.relayer.address().to_bytes(),
                fee,
            },
        };
        if !verify(&Proof::from_le_bytes(self.data.proof), inputs) {
            return Err(ShieldedPoolError::InvalidProof.into());
        }

        // Spend the note: create its account, paid by the relayer.
        let bump = [self.nullifier_bump];
        let seeds = [
            Seed::from(NULLIFIER_SEED),
            Seed::from(&self.denomination),
            Seed::from(self.data.nullifier_hash),
            Seed::from(&bump),
        ];
        pinocchio_system::create_account_with_minimum_balance_signed(
            self.accounts.nullifier,
            Nullifier::LEN,
            &crate::ID,
            self.accounts.relayer,
            None,
            &[Signer::from(&seeds)],
        )?;
        self.accounts.nullifier.try_borrow_mut()?[0] = Nullifier::TAG;

        // The pool is the program's, so its lamports move directly.
        debit(self.accounts.pool, denomination)?;
        credit(self.accounts.recipient, denomination - fee)?;
        credit(self.accounts.relayer, fee)
    }
}

fn debit(account: &mut AccountView, lamports: u64) -> ProgramResult {
    let balance = account
        .lamports()
        .checked_sub(lamports)
        .ok_or(ProgramError::InsufficientFunds)?;
    account.set_lamports(balance);
    Ok(())
}

fn credit(account: &mut AccountView, lamports: u64) -> ProgramResult {
    let balance = account
        .lamports()
        .checked_add(lamports)
        .ok_or(ProgramError::ArithmeticOverflow)?;
    account.set_lamports(balance);
    Ok(())
}
```

The cheap checks come first, before the proof's verification, which is most of the instruction's
compute:

- **The nullifier is the note's PDA, at its canonical bump.** It's seeded by the denomination and
  the nullifier hash, so each note has one address per pool. A bump from the transaction would
  let the same note have several addresses, and pay out once at each; `find_program_address`
  allows only one.
- **The nullifier doesn't exist yet.** If it does, the note is spent: `NullifierSpent`.
- **`fee` is at most the denomination**, so the payout can't take more than the note is worth:
  `FeeTooHigh`.
- **`root` is one of the pool's recent roots**, so a proof against a tree the pool never had, or
  had too long ago, is refused: `UnknownRoot`.

Then the public inputs, the generated `Withdrawal`: `root` and `nullifier_hash` from the
instruction, the two addresses from the transaction's accounts and `fee` as the relayer sent it.
Each address goes in as its 32 bytes, and the crate splits it into the `Address`'s two halves. A relayer who swaps the recipient for
their own, or raises the fee, has a proof of another statement, which fails with `InvalidProof`.

Two more checks guard the payout:

- **The recipient isn't the pool or the nullifier.** The proof binds the recipient, but the
  depositor chose it, and a payout to one of the pool's own accounts would debit and credit the
  same lamports. The payout is between three distinct accounts.
- **The lamport arithmetic is checked.** `fee <= denomination` was checked above, so
  `denomination - fee` can't wrap, and `debit` and `credit` fail rather than wrap. The runtime
  also refuses any transaction that leaves the pool below rent exemption.

The pool is owned by the program, so its lamports move directly, with no CPI. The recipient needs
no SOL and signs nothing: the relayer pays the transaction fee and the nullifier's rent, and is
paid back by `fee`.
</Step>

### Name the errors

`InvalidAccountOwner`, `InvalidAccountData`, `InvalidSeeds`, `AccountAlreadyInitialized`,

```rust title="programs/shielded-pool/src/errors.rs"
use pinocchio::error::{ProgramError, ToStr};

/// The program's own errors, as `ProgramError::Custom` codes.
#[derive(Clone, Copy)]
#[repr(u32)]
pub enum ShieldedPoolError {
    InvalidProof = 0,
    UnknownRoot,
    FeeTooHigh,
    TreeFull,
    NullifierSpent,
}

impl From<ShieldedPoolError> for ProgramError {
    fn from(e: ShieldedPoolError) -> Self {
        ProgramError::Custom(e as u32)
    }
}

impl TryFrom<u32> for ShieldedPoolError {
    type Error = ProgramError;

    fn try_from(code: u32) -> Result<Self, Self::Error> {
        match code {
            0 => Ok(Self::InvalidProof),
            1 => Ok(Self::UnknownRoot),
            2 => Ok(Self::FeeTooHigh),
            3 => Ok(Self::TreeFull),
            4 => Ok(Self::NullifierSpent),
            _ => Err(ProgramError::InvalidArgument),
        }
    }
}

/// What the entrypoint logs: the name, then what it means.
impl ToStr for ShieldedPoolError {
    fn to_str(&self) -> &'static str {
        match self {
            Self::InvalidProof => "InvalidProof: invalid proof",
            Self::UnknownRoot => "UnknownRoot: unknown or stale merkle root",
            Self::FeeTooHigh => "FeeTooHigh: fee exceeds denomination",
            Self::TreeFull => "TreeFull: tree is full",
            Self::NullifierSpent => "NullifierSpent: nullifier already spent",
        }
    }
}
```

```ts title="tests/shielded-pool.test.ts"
// The program's instruction discriminators.
const INITIALIZE = 0;
const DEPOSIT = 1;
const WITHDRAW = 2;

// An instruction's data: its discriminator, then its arguments' bytes.
const instructionData = (discriminator: number, ...args: Uint8Array[]) =>
  new Uint8Array(Buffer.concat([Uint8Array.of(discriminator), ...args]));

// A u64, little-endian, as the program and the PDA seeds read it.
function u64le(x: bigint) {
  const out = new Uint8Array(8);
  new DataView(out.buffer).setBigUint64(0, x, true);
  return out;
```

```ts title="tests/shielded-pool.test.ts"
test("deposit, someone else deposits, withdraw through a relayer, once", async () => {
  const program = address("Fg6PaFpoGXkYsidMpWTK6W2BeZ7FEfcYkg476zPFsLnS"); // the program's `ID`
  const svm = vm({ [program]: deployed("shielded-pool") });
  const system = { address: address("11111111111111111111111111111111"), role: AccountRole.READONLY };
  const writable = (a: Address) => ({ address: a, role: AccountRole.WRITABLE });
  const signer = (s: KeyPairSigner) => ({ address: s.address, role: AccountRole.WRITABLE_SIGNER, signer: s });

  // A pool of 1 SOL notes. Its empty root is the circuit's.
  const DENOMINATION = 1_000_000_000n;
  const [pool] = await getProgramDerivedAddress({ programAddress: program, seeds: ["pool", u64le(DENOMINATION)] });
  const authority = await funded(svm);
  const initialized = await send(svm, authority, {
    programAddress: program,
    accounts: [writable(pool), signer(authority), system],
    data: instructionData(INITIALIZE, u64le(DENOMINATION)),
  });
  console.log(`initialize in ${initialized.computeUnitsConsumed()} CU`);
  let tip = Path.first();
  const account = svm.getAccount(pool);
  expect(account.exists && account.data.subarray(24, 56)).toEqual(tip.treeRoot().toBytes());

  // Deposit `note` at the next free leaf, and move the tip past it.
  async function deposit(note: Note) {
    const leaf = Note.commitment(note);
    const append = Append.of(tip, leaf);
    const proof = deposits.prove({ path: tip, append });
    const depositor = await funded(svm);
    const sent = await send(svm, depositor, {
      programAddress: program,
      accounts: [writable(pool), signer(depositor), system],
      data: instructionData(DEPOSIT, leaf.toBytes(), append.newRoot.toBytes(), proof.toBytes()),
    });
    console.log(`deposit ${append.index} verified onchain in ${sent.computeUnitsConsumed()} CU`);
    const path = tip;
    tip = tip.next(leaf);
    return { path, leaf };
  }

  const mine = newNote();
  let { path } = await deposit(mine);
  // Someone deposits after me: my wallet updates my path.
  const later = tip;
  const { leaf } = await deposit(newNote());
  path = path.update(later, leaf);

  // A relayer submits my withdrawal to a fresh address, for a fee.
  const relayer = await funded(svm);
  const recipient = (await generateKeyPairSigner()).address;
  const fee = 10_000_000n;
  const statement = Withdrawal.of(mine, path, recipient, relayer.address, fee);
  const proof = withdrawals.prove({ note: mine, path, withdrawal: statement });
  const { root, nullifierHash } = statement;
  const [nullifier] = await getProgramDerivedAddress({
    programAddress: program,
    seeds: ["nullifier", u64le(DENOMINATION), nullifierHash.toBytes()],
  });
  const withdraw = (to: Address) => ({
    programAddress: program,
    accounts: [writable(pool), writable(nullifier), writable(to), signer(relayer), system],
    data: instructionData(WITHDRAW, proof.toBytes(), root.toBytes(), nullifierHash.toBytes(), u64le(fee)),
  });

  // The proof pays only the recipient it was made for.
  const thief = (await generateKeyPairSigner()).address;
  await expect(send(svm, relayer, withdraw(thief))).rejects.toThrow(/InvalidProof/);

  const sent = await send(svm, relayer, withdraw(recipient));
  console.log(`withdrawal verified onchain in ${sent.computeUnitsConsumed()} CU`);
  expect(svm.getBalance(recipient)).toBe(DENOMINATION - fee);

  // The nullifier is spent: the same note can't come out twice.
  await expect(send(svm, relayer, withdraw(recipient))).rejects.toThrow(/NullifierSpent/);
}, 60_000);
```

## What you built

A shielded pool: 1 SOL went in from one wallet and came out at another, and nothing onchain links
the two. The new ideas:

- **Commitments in a Merkle tree, and nullifiers.** 02's commitments became 03's leaves. A
  deposit's commitment is a leaf; a withdrawal proves the note behind *some* leaf is yours,
  against a root the program remembers, with 03's Merkle path. Every
  deposit in the tree is a candidate, so the anonymity set is the whole pool. Each note has one
  nullifier hash, which the program records as a PDA, so a note pays out once, and the hash
  reveals nothing about which commitment it belongs to.
- **Two circuits and a wallet sharing a crate.** `pool` is ordinary Rust. Both circuits compile
  its `Path::root` into constraints, and the TypeScript wallet runs its `first`, `next` and
  `update` through the generated clients.
- **The chain never hashes.** The deposit circuit proves the new root, so the program stores roots
  and verifies proofs, and the circuits and the chain can't disagree about a hash.
- **A Pinocchio program** around the two generated verifier crates: a file per instruction, a
  PDA per pool and per nullifier, and every account check written out.

The pool hides *which* deposit a withdrawal spends, not *how much*: every note in a pool is the
same size, which is why range proofs had little to do here. It also can't hide timing. A withdrawal right after the only deposit links them anyway.
A deposit proof binds the current root and next index, so two deposits racing for the same slot
can't both land: a real wallet reads the pool's state just before proving, and proves again if
another deposit wins.

<Callout type="warn" title="Before you deploy">
The keys `xark build` made are single-party: sound unless whoever made them kept their randomness.
A pool that holds value needs keys from a ceremony, and an audit. See
[The trusted setup](/docs/trust/trusted-setup).
</Callout>

The finished example, with host tests of each account check and a test of more refusals (another
fee, an unknown root), is
[04-shielded-pool](https://github.com/blueshift-gg/xark-examples/tree/main/04-shielded-pool) in
xark-examples.

A note here has one nullifier for its whole life, and a pool needs no more. The next tutorial,
anonymous voting, keeps the tree of commitments and scopes the nullifier: a voter's changes with
every poll, so each poll counts them once and no two polls can be linked. Fixed denominations are
this pool's other limit: you can't pay someone 3.7 SOL, or split a note. After voting,
[06 · Shielded transfer](/docs/tutorials/06-shielded-transfer) lets notes carry any amount, and
that is where range proofs become essential.

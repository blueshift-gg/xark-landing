---
title: "03 · Token claim"
description: Merkle trees in a circuit. Airdrop an SPL token to a list of up to a million addresses, with one 32-byte root onchain. A Merkle path as a private input, a tree builder the client runs from the circuit's Rust, and a Pinocchio program that pays each address once.
---

In this tutorial you'll build a token airdrop. A distributor publishes one 32-byte root for a list
of (Solana address, amount) pairs and funds a vault with the tokens. Each address on the list
proves it's there, for its amount, and a Solana program pays it, once.

The new idea is the **Merkle tree in a circuit**. [01](/docs/tutorials/01-over-9000) and
[02](/docs/tutorials/02-zkyc) proved things about one value: a number, then one committed identity.
A list of a million can't be a public input, but its Merkle root can: one field element that fixes
every entry. Each leaf is the Poseidon2 hash of a claimant's Solana address (as two halves) and the
amount they're owed. The claimant proves their leaf is under the published root, with the path to
it as a private input, and that proof is what entitles them to claim the amount. Around it:

- a **tree builder written once**, in the circuit crate's Rust, that the distributor and the
  claimant both call from TypeScript, so everyone hashes as the circuit does;
- a **public claimant and amount**, so the program remembers who claimed with one receipt account
  per address;
- an **SPL vault** that a Pinocchio program pays from, signing as its owner.

By the end you'll have the same pieces as in [01](/docs/tutorials/01-over-9000) and
[02](/docs/tutorials/02-zkyc): a circuit and its tests, a TypeScript client, a Solana program,
and an end-to-end test where an address on the list claims its tokens and every other claim is
refused.

<Step>
### Describe a claim

A claim is one entry of the list: an address, and how many tokens it gets. Replace
`circuits/token-claim/src/lib.rs` with:

```rust title="circuits/token-claim/src/lib.rs"
use xark::prelude::*;
use xark_merkle::poseidon2::merkle_root;
#[cfg(not(xark))]
use xark_merkle::tree::{self, Tree};
#[cfg(not(xark))]
use xark_poseidon2::hash2;

/// One entry of the list: `amount` tokens for the wallet `claimant`.
#[input]
pub struct Claim {
    pub claimant: Address,
    pub amount: u64,
}

#[input]
impl Claim {
    /// The claim's leaf: `Poseidon2(claimant.hi, claimant.lo, amount)`.
    pub fn leaf(&self) -> Field {
        let [hi, lo] = self.claimant.to_fields();
        xark_poseidon2::hash([hi, lo, Field::from(self.amount)])
    }
}
```

The claimant is an `Address`, a Solana address as two field elements, as 02's holder was. A
claim's **leaf** is the Poseidon2 hash of its three field elements, and `#[input] impl` puts
`Claim.leaf` in the TypeScript client, as `Identity.commitment` was in 02. `to_fields` gives the
address's two halves, `hi` and `lo`. See [Hashes](/docs/gadgets/hashes).
</Step>

<Step>
### Write the tree

A Merkle tree hashes its leaves in pairs, then those hashes in pairs, up to a single **root**.
Changing any leaf changes the root, so the root commits to the whole list. To show a leaf is in it,
you give the leaf's **path**: its index, and the sibling at each level. Hashing up from the leaf
with those siblings must land on the root, and Poseidon2's collision resistance means only a leaf
that's really there can. That check is 20 hashes, whatever the list's length.

This list is a Merkle tree of depth 20: the claims' leaves in order, then an empty leaf in every
slot left, up to 2^20. Its root is what the distributor publishes. Append to
`circuits/token-claim/src/lib.rs`:

```rust title="circuits/token-claim/src/lib.rs"
/// Tree depth: up to 2^20 claims.
pub const DEPTH: usize = 20;

/// The empty leaf, ASCII `xarkzero`: no claim's leaf is this value, so the
/// padding after the list can't be claimed.
pub const EMPTY_LEAF: u64 = 0x7861_726b_7a65_726f;

/// The empty list, as a distributor builds it in Rust: push each claim's leaf, then
/// take its `root()` and each claim's `path(i)`.
#[cfg(not(xark))]
pub fn list() -> Tree<DEPTH> {
    Tree::poseidon2(Field::from(EMPTY_LEAF))
}

/// A leaf's authentication path: its index, and its sibling at each height.
#[input]
pub struct Path {
    pub index: u32,
    pub siblings: [Field; 20],
}

#[input]
impl Path {
    /// The root of the tree with `leaf` at this path.
    pub fn root(&self, leaf: Field) -> Field {
        merkle_root(leaf, self.siblings, Field::from(self.index).to_bits::<DEPTH>())
    }

    /// The first leaf's path, in the empty list: every sibling is empty.
    #[cfg(not(xark))]
    pub fn first() -> Path {
        list().path(0).into()
    }

    /// For the next free leaf's path, the root of the list so far.
    #[cfg(not(xark))]
    pub fn list_root(&self) -> Field {
        self.root(Field::from(EMPTY_LEAF))
    }

    /// The next free leaf's path, once `leaf` is added at this one.
    #[cfg(not(xark))]
    pub fn next(self, leaf: Field) -> Path {
        assert!((self.index as usize) < (1 << DEPTH) - 1, "the list is full");
        let index = self.index + 1;
        let empty = list();
        let mut siblings = self.siblings;
        let mut node = leaf;
        for (i, sibling) in siblings.iter_mut().enumerate() {
            let (mine, next) = (self.index >> i, index >> i);
            let old = *sibling;
            if next != mine {
                // A new subtree: its left sibling is this leaf's, its right is empty.
                *sibling = if next & 1 == 1 { node } else { empty.empty_subtrees()[i] };
            }
            node = node_of(mine, node, old);
        }
        Path { index, siblings }
    }

    /// This path, once `leaf` is added at `later`, a later leaf's path.
    #[cfg(not(xark))]
    pub fn update(self, later: Path, leaf: Field) -> Path {
        assert!(later.index > self.index, "`later` must be a later leaf's path");
        let mut siblings = self.siblings;
        let mut node = leaf;
        for (i, (sibling, beside)) in siblings.iter_mut().zip(later.siblings).enumerate() {
            let at = later.index >> i;
            if at == self.index >> i ^ 1 {
                *sibling = node;
            }
            node = node_of(at, node, beside);
        }
        Path { index: self.index, siblings }
    }
}

/// A path out of a `Tree`, as the circuit takes it.
#[cfg(not(xark))]
impl From<tree::Path<DEPTH>> for Path {
    fn from(path: tree::Path<DEPTH>) -> Path {
        Path { index: path.index as u32, siblings: path.siblings }
    }
}

/// The parent of `node`, at position `at` in its level, and its `sibling`.
#[cfg(not(xark))]
fn node_of(at: u32, node: Field, sibling: Field) -> Field {
    if at & 1 == 0 { hash2(node, sibling) } else { hash2(sibling, node) }
}
```

`root` is the one function the circuit calls. `to_bits` turns the index into the 20 bits that
steer each level, and bounds it below 2^20. `merkle_root`, from `xark_merkle::poseidon2`, folds the
path up from the leaf. At each level, `cond_swap` puts the running node on the left or the right by
that level's bit, and constrains the bit to 0 or 1; then `hash2`, Poseidon2's 2-to-1 hash, makes
the parent. See [Commitments & Merkle trees](/docs/gadgets/commitments).

The rest is the **builder**, host-only (`#[cfg(not(xark))]`), so it costs the circuit nothing:

- `list()` is the empty list as `xark-merkle`'s host tree, a `Tree` with the same Poseidon2 nodes
  and this empty leaf. A distributor in Rust pushes each claim's leaf and takes its `root()` and
  each claim's `path(i)`; `From` turns that path into the circuit's `Path`.
- `Path::first()` is the first leaf's path, in an empty list.
- The distributor keeps the path of the next free leaf, the **tip**. `tip.list_root()` is the
  list's root so far, and `tip.next(leaf)` the next tip once `leaf` is added.
- `path.update(tip, leaf)` keeps an earlier path current when `leaf` is added at `tip`.

`Tree` isn't an `#[input]` type, so it stays in Rust. `#[input] impl` puts `Path`'s functions in
the client, so a distributor in TypeScript builds the tree, and a claimant checks their path, with
this same Rust. See [On the host](/docs/reference/language#on-the-host).

A leaf and a node can't be confused. The leaf is Poseidon2's sponge over three elements, and a node
its 2-to-1 compression, two different functions; and every path is exactly 20 levels, so no node
passes as a leaf at a shallower one. The empty leaf is a constant no claim hashes to, so the
padding can't be claimed.
</Step>

<Step>
### Write the circuit and its tests

Append the circuit and three tests:

```rust title="circuits/token-claim/src/lib.rs"
#[circuit]
pub fn token_claim(path: Private<Path>, root: Public<Field>, claim: Public<Claim>) {
    require_eq(path.root(claim.leaf()), root);
}

#[cfg(test)]
mod tests {
    use super::*;

    fn claim(n: u8, amount: u64) -> Claim {
        Claim { claimant: [n; 32].into(), amount }
    }

    /// The list's root and every claim's path, as a distributor builds them.
    fn of(claims: &[Claim]) -> (Field, Vec<Path>) {
        let mut tree = list();
        tree.extend(claims.iter().map(Claim::leaf));
        let paths = (0..claims.len()).map(|i| tree.path(i).into()).collect();
        (tree.root(), paths)
    }

    /// One path at a time (`Path::first`, `next`, `update`), with no tree, agrees
    /// with `Tree`'s, path for path.
    #[test]
    fn one_path_at_a_time_agrees_with_the_tree() {
        let leaves: Vec<Field> = (1..=11).map(|n| claim(n, u64::from(n) * 100).leaf()).collect();
        let mut tree = list();
        let mut tip = Path::first(); // the next free leaf's path
        let mut paths: Vec<Path> = Vec::new();
        assert_eq!(tip.list_root(), tree.root());
        for &leaf in &leaves {
            paths = paths.into_iter().map(|p| p.update(tip, leaf)).collect();
            paths.push(tip);
            tip = tip.next(leaf);
            tree.push(leaf);
            assert_eq!(tip.list_root(), tree.root());
            for (i, path) in paths.iter().chain([&tip]).enumerate() {
                let want = tree.path(i);
                assert_eq!((path.index as usize, path.siblings), (want.index, want.siblings));
            }
        }
    }

    #[test]
    fn everyone_on_the_list_claims_their_amount() {
        let claims = [claim(1, 500), claim(2, 1_000), claim(3, 250)];
        let (root, paths) = of(&claims);
        for (path, c) in paths.iter().zip(claims) {
            token_claim(*path, root, c).unwrap();
        }
    }

    #[test]
    fn nothing_else_is_on_the_list() {
        let claims = [claim(1, 500), claim(2, 1_000), claim(3, 250)];
        let (root, paths) = of(&claims);
        assert!(token_claim(paths[0], root, claim(1, 501)).is_err()); // another amount
        assert!(token_claim(paths[1], root, claim(1, 500)).is_err()); // someone else's path
        assert!(token_claim(paths[0], root, claim(9, 500)).is_err()); // not on the list
        let (other, _) = of(&[claim(1, 500)]);
        assert!(token_claim(paths[0], other, claims[0]).is_err()); // another list
        // The slot after the list holds the empty leaf, which no claim is.
        let (_, longer) = of(&[claims[0], claims[1], claims[2], claim(4, 1)]);
        assert!(token_claim(longer[3], root, claim(4, 1)).is_err());
    }
}
```

The whole circuit is one line: the path's root over the claim's leaf is the published root. The
`path` is private; the `root` and the `claim` are public.

The tests build the list as a distributor in Rust will, with `of`: every leaf into `list()`, then
the `Tree`'s root and each claim's path. The first checks the one-path-at-a-time builder, which the
TypeScript client will use, against the `Tree`, root and every path, for lists of 0 to 11 claims.
The other two check that everyone on a list of three can claim their amount, and nothing else can:
another amount, someone else's path, an address that isn't on the list, another list's root, or
the empty slot after it.
</Step>

### Build the list and prove from TypeScript

Install the test's packages, from the `package.json` that `xark add program` wrote:

Replace `tests/token-claim.test.ts` with:

```ts title="tests/token-claim.test.ts"
import { generateKeyPairSigner } from "@solana/kit";
import { circuit } from "@blueshift-gg/xark/testing";
import { Claim, Path, TokenClaim, type Field, type PathValue, type TokenClaimProver } from "../clients/token-claim/ts/token_claim";

let prover: TokenClaimProver;
beforeAll(async () => {
  // The circuit's build output and keys. Its `client.wasm` is the crate's Rust:
  // Claim.leaf, Path.
  prover = await TokenClaim.prover(circuit("token-claim"), { digest: TokenClaim.digest });
});

/** The distributor's list: its root, and each claim's path. */
function list(claims: Claim[]): { root: Field; paths: PathValue[] } {
  let tip = Path.first(); // the next free leaf's path
  let paths: PathValue[] = [];
  for (const claim of claims) {
    const leaf = Claim.leaf(claim);
    paths = paths.map((p) => p.update(tip, leaf));
    paths.push(tip);
    tip = tip.next(leaf);
  }
  return { root: tip.listRoot(), paths };
}

/** A new wallet's address. */
const wallet = async () => (await generateKeyPairSigner()).address;

test("a claimant on the list has a proof", async () => {
  const claims: Claim[] = [
    { claimant: await wallet(), amount: 500 },
    { claimant: await wallet(), amount: 1_000 },
    { claimant: await wallet(), amount: 250 },
  ];
  const { root, paths } = list(claims);
  expect(paths[1].root(Claim.leaf(claims[1]))).toEqual(root);

  const proof = prover.prove({ path: paths[1], root, claim: claims[1] });

  // The verifier sees the root and the claim, and nothing of the path.
  const verifier = await TokenClaim.verifier(circuit("token-claim").verifyingKey);
  expect(verifier.verify(proof.toBytes(), { root, claim: claims[1] })).toBe(true);
  expect(verifier.verify(proof.toBytes(), { root, claim: { ...claims[1], amount: 1_001 } })).toBe(false);
});

test("an address not on the list has no proof", async () => {
  const { root, paths } = list([{ claimant: await wallet(), amount: 500 }]);
  const stranger = { claimant: await wallet(), amount: 500 };
  expect(() => prover.prove({ path: paths[0], root, claim: stranger })).toThrow(/path\.root\(claim\.leaf\(\)\)/);
});
```

A claimant is a wallet's address as @solana/kit has it: the client splits it into the circuit's
two halves. `circuit("token-claim")` reads the circuit's build output and its keys, and
`client.wasm` among them is the crate's Rust compiled for the client. `list` is the distributor: it adds each claim at
the tip, updates the paths it has already handed out, and publishes `tip.listRoot()`. Every hash in
it is the Rust you wrote, so the root it makes is the one the circuit checks. A claimant can check
the path they're given the same way, with `path.root(Claim.leaf(claim))`, as the first test
does. See [Call the circuit's Rust from TypeScript](/docs/guides/typescript-clients#call-the-circuits-rust-from-typescript).

`list` updates every path at every step, which is fine for a few claims and too slow for a
million. A real distributor builds the tree once in Rust, with `list()` as the circuit's tests do
(`Tree::extend` hashes each node once), and hands each claimant its path.

The program has two instructions. `initialize` stores a list's root and creates its vault, a
token account the program controls, funded by the distributor. `claim` checks a proof against
that root, records a receipt and pays. It starts from the program `xark add program` wrote in
`programs/token-claim/`. Add its dependencies, and remove the starter's instruction:

```sh
cargo add -p token-claim-program pinocchio-system@0.6 pinocchio-token@0.7
cargo add -p token-claim-program solana-address@2 --features curve25519 --target 'cfg(not(target_os = "solana"))'

```

`pinocchio-system` creates accounts and `pinocchio-token` moves tokens, both through calls to
those programs. Onchain, the program derives its PDAs with the runtime's syscalls; `solana-address`
derives them in software for a build on your machine, which `xark test` makes to run the program's
Rust tests. The program is laid out as Pinocchio programs usually are, one file per instruction:

```text

├── state.rs         the distributor's account
├── errors.rs        the program's own error
├── helpers.rs       account creation, and a log
```

Replace `programs/token-claim/src/lib.rs` with the entrypoint:

```rust title="programs/token-claim/src/lib.rs"
#![cfg_attr(not(test), no_std)]
pub mod errors;
pub mod helpers;
pub mod instructions;
pub mod state;

pub use errors::*;
pub use instructions::*;

use pinocchio::{AccountView, Address, ProgramResult, error::ProgramError, program_entrypoint};

program_entrypoint!(process_instruction);
#[cfg(not(test))]
pinocchio::nostd_panic_handler!();
#[cfg(not(test))]
pinocchio::no_allocator!();

fn process_instruction(program_id: &Address, accounts: &mut [AccountView], data: &[u8]) -> ProgramResult {
    // Log the error's name, so a client sees `InvalidProof` and not a bare code.
    dispatch(program_id, accounts, data).inspect_err(|e| helpers::log(e.to_str::<TokenClaimError>()))
}

/// The first byte of the data says which instruction; the rest is its arguments.
fn dispatch(program_id: &Address, accounts: &mut [AccountView], data: &[u8]) -> ProgramResult {
    match data.split_first() {
        Some((Initialize::DISCRIMINATOR, data)) => Initialize::try_from((program_id, data, accounts))?.process(),
        Some((Claim::DISCRIMINATOR, data)) => Claim::try_from((program_id, data, &*accounts))?.process(),
        _ => Err(ProgramError::InvalidInstructionData),
    }
}
```

Each instruction will be three structs: its accounts, its instruction data, and the two together,
with a `process` that does the work. Each is built with `TryFrom`, which runs every check, so
`process` only ever sees accounts and data that passed. The program takes the address it's
deployed at as `program_id`, so the test can deploy it anywhere. As in 01, the `cfg(not(test))`
lines leave out the panic handler and allocator for the Rust tests.

The program's state is one account, the distributor. Create
`programs/token-claim/src/state.rs`:

```rust title="programs/token-claim/src/state.rs"
use pinocchio::{AccountView, Address, account::{Ref, RefMut}, error::ProgramError};

pub const DISTRIBUTOR_SEED: &[u8] = b"distributor";
pub const VAULT_SEED: &[u8] = b"vault";
pub const CLAIMED_SEED: &[u8] = b"claimed";
/// An SPL token account's size.
pub const TOKEN_ACCOUNT_LEN: usize = 165;

/// A list's distributor: its root, its bump and its vault's bump. Every field is
/// bytes, so the layout has no padding and any address is aligned.
#[repr(C)]
pub struct Distributor {
    pub root: [u8; 32],
    pub bump: u8,
    pub vault_bump: u8,
}

impl Distributor {
    pub const LEN: usize = size_of::<Self>();

    /// The distributor in `account`: the program's, and of this size.
    pub fn load<'a>(account: &'a AccountView, program_id: &Address) -> Result<Ref<'a, Self>, ProgramError> {
        if !account.owned_by(program_id) || account.data_len() != Self::LEN {
            return Err(ProgramError::InvalidAccountData);
        }
        // SAFETY: the data is `LEN` bytes, and `Self` is bytes only (alignment 1).
        Ok(Ref::map(account.try_borrow()?, |data| unsafe { &*(data.as_ptr() as *const Self) }))
    }

    pub fn load_mut<'a>(account: &'a mut AccountView, program_id: &Address) -> Result<RefMut<'a, Self>, ProgramError> {
        if !account.owned_by(program_id) || account.data_len() != Self::LEN {
            return Err(ProgramError::InvalidAccountData);
        }
        // SAFETY: as in `load`.
        Ok(RefMut::map(account.try_borrow_mut()?, |data| unsafe { &mut *(data.as_mut_ptr() as *mut Self) }))
    }
}
```

`Distributor` is the account's bytes as a struct: 32 of root, then two bumps, 34 in all. `load`
is the only way the program reads one, so the owner and size checks run on every read. The bumps
are stored so that a claim can check the vault's address with one hash, without searching for
the bump again.

Only one failure is the program's own: a proof that doesn't verify. Everything else it refuses,
from a missing signature to a receipt that already exists, has a built-in `ProgramError` that
clients already know. `xark add program` already wrote that one error in
`programs/token-claim/src/errors.rs`: `TokenClaimError::InvalidProof`, custom error 0. Its
`TryFrom<u32>` and `ToStr` let the entrypoint's `to_str` turn an error back into its name, built-in
or not, so a failed proof logs `InvalidProof: invalid proof`. Keep it as it is.
</Step>

```rust title="programs/token-claim/src/instructions/initialize.rs"
use pinocchio::{AccountView, Address, ProgramResult, cpi::Seed, error::ProgramError};
use pinocchio_token::instructions::{InitializeAccount3, Transfer};

use crate::{helpers::create, state::{DISTRIBUTOR_SEED, Distributor, TOKEN_ACCOUNT_LEN, VAULT_SEED}};

/// Accounts: authority (signer), distributor, vault, mint, the authority's token
/// account, the token program, the system program.
pub struct InitializeAccounts<'a> {
    pub authority: &'a AccountView,
    pub distributor: &'a mut AccountView,
    pub vault: &'a AccountView,
    pub mint: &'a AccountView,
    pub authority_token: &'a AccountView,
}

impl<'a> TryFrom<&'a mut [AccountView]> for InitializeAccounts<'a> {
    type Error = ProgramError;
    fn try_from(accounts: &'a mut [AccountView]) -> Result<Self, Self::Error> {
        let [authority, distributor, vault, mint, authority_token, ..] = accounts else {
            return Err(ProgramError::NotEnoughAccountKeys);
        };
        if !authority.is_signer() {
            return Err(ProgramError::MissingRequiredSignature);
        }
        Ok(Self { authority, distributor, vault, mint, authority_token })
    }
}

/// `root` (32 B) ‖ `total` (8 B, little-endian).
pub struct InitializeInstructionData {
    pub root: [u8; 32],
    pub total: u64,
}

impl TryFrom<&[u8]> for InitializeInstructionData {
    type Error = ProgramError;
    fn try_from(data: &[u8]) -> Result<Self, Self::Error> {
        let (root, total) = data.split_first_chunk::<32>().ok_or(ProgramError::InvalidInstructionData)?;
        let total: [u8; 8] = total.try_into().map_err(|_| ProgramError::InvalidInstructionData)?;
        Ok(Self { root: *root, total: u64::from_le_bytes(total) })
    }
}

pub struct Initialize<'a> {
    pub program_id: &'a Address,
    pub accounts: InitializeAccounts<'a>,
    pub data: InitializeInstructionData,
    pub bump: u8,
    pub vault_bump: u8,
}

impl<'a> TryFrom<(&'a Address, &'a [u8], &'a mut [AccountView])> for Initialize<'a> {
    type Error = ProgramError;
    fn try_from((program_id, data, accounts): (&'a Address, &'a [u8], &'a mut [AccountView])) -> Result<Self, Self::Error> {
        let accounts = InitializeAccounts::try_from(accounts)?;
        let data = InitializeInstructionData::try_from(data)?;

        // The distributor, at ["distributor", root]: one per list.
        let (address, bump) = Address::find_program_address(&[DISTRIBUTOR_SEED, &data.root], program_id);
        if accounts.distributor.address() != &address {
            return Err(ProgramError::InvalidSeeds);
        }
        // The vault, at ["vault", distributor]: a token account the distributor owns.
        let (address, vault_bump) = Address::find_program_address(&[VAULT_SEED, accounts.distributor.address().as_ref()], program_id);
        if accounts.vault.address() != &address {
            return Err(ProgramError::InvalidSeeds);
        }
        Ok(Self { program_id, accounts, data, bump, vault_bump })
    }
}

impl<'a> Initialize<'a> {
    pub const DISCRIMINATOR: &'a u8 = &0;

    pub fn process(&mut self) -> ProgramResult {
        let Self { program_id, accounts, data, bump, vault_bump } = self;

        let bump_seed = [*bump];
        let seeds = [Seed::from(DISTRIBUTOR_SEED), Seed::from(&data.root), Seed::from(&bump_seed)];
        create(accounts.authority, accounts.distributor, Distributor::LEN, program_id, &seeds)?;

        let vault_bump_seed = [*vault_bump];
        let vault_seeds = [Seed::from(VAULT_SEED), Seed::from(accounts.distributor.address().as_ref()), Seed::from(&vault_bump_seed)];
        create(accounts.authority, accounts.vault, TOKEN_ACCOUNT_LEN, &pinocchio_token::ID, &vault_seeds)?;
        InitializeAccount3::new(accounts.vault, accounts.mint, accounts.distributor.address()).invoke()?;

        let mut distributor = Distributor::load_mut(accounts.distributor, program_id)?;
        distributor.root = data.root;
        distributor.bump = *bump;
        distributor.vault_bump = *vault_bump;
        drop(distributor);

        Transfer::new(accounts.authority_token, accounts.vault, accounts.authority, data.total).invoke()
    }
}
```

The distributor's address comes from the root, so there's one per list, and the claims later
trust what it holds. `find_program_address` searches for each PDA's bump once, here, and
`process` stores both. The vault is an SPL token account whose owner is the distributor. No
wallet holds a key for that address: only this program, signing with the distributor's seeds, can
move the vault's tokens. The last line funds it, from a token account the authority signs for.
</Step>

Create `programs/token-claim/src/instructions/claim.rs`:

```rust title="programs/token-claim/src/instructions/claim.rs"
use pinocchio::{AccountView, Address, ProgramResult, cpi::{Seed, Signer}, error::ProgramError};
use pinocchio_token::instructions::Transfer;
use token_claim_verifier::{Proof, PublicInputs, verify};

use crate::{TokenClaimError, helpers::create, state::{CLAIMED_SEED, DISTRIBUTOR_SEED, Distributor, VAULT_SEED}};

/// Accounts: claimant (signer), distributor, vault, receipt, the claimant's token
/// account, the token program, the system program.
pub struct ClaimAccounts<'a> {
    pub claimant: &'a AccountView,
    pub distributor: &'a AccountView,
    pub vault: &'a AccountView,
    pub receipt: &'a AccountView,
    pub claimant_token: &'a AccountView,
}

impl<'a> TryFrom<(&'a Address, &'a [AccountView])> for ClaimAccounts<'a> {
    type Error = ProgramError;
    fn try_from((program_id, accounts): (&'a Address, &'a [AccountView])) -> Result<Self, Self::Error> {
        let [claimant, distributor, vault, receipt, claimant_token, ..] = accounts else {
            return Err(ProgramError::NotEnoughAccountKeys);
        };
        if !claimant.is_signer() {
            return Err(ProgramError::MissingRequiredSignature);
        }
        let vault_bump = Distributor::load(distributor, program_id)?.vault_bump;
        let vault_address = Address::derive_address(&[VAULT_SEED, distributor.address().as_ref()], Some(vault_bump), program_id);
        if vault.address() != &vault_address {
            return Err(ProgramError::InvalidSeeds);
        }
        Ok(Self { claimant, distributor, vault, receipt, claimant_token })
    }
}

/// `proof` (256 B) ‖ `amount` (8 B, little-endian).
pub struct ClaimInstructionData<'a> {
    pub proof: &'a [u8; 256],
    pub amount: u64,
}

impl<'a> TryFrom<&'a [u8]> for ClaimInstructionData<'a> {
    type Error = ProgramError;
    fn try_from(data: &'a [u8]) -> Result<Self, Self::Error> {
        let (proof, amount) = data.split_first_chunk::<256>().ok_or(ProgramError::InvalidInstructionData)?;
        let amount: [u8; 8] = amount.try_into().map_err(|_| ProgramError::InvalidInstructionData)?;
        Ok(Self { proof, amount: u64::from_le_bytes(amount) })
    }
}

pub struct Claim<'a> {
    pub program_id: &'a Address,
    pub accounts: ClaimAccounts<'a>,
    pub data: ClaimInstructionData<'a>,
}

impl<'a> TryFrom<(&'a Address, &'a [u8], &'a [AccountView])> for Claim<'a> {
    type Error = ProgramError;
    fn try_from((program_id, data, accounts): (&'a Address, &'a [u8], &'a [AccountView])) -> Result<Self, Self::Error> {
        Ok(Self {
            program_id,
            accounts: ClaimAccounts::try_from((program_id, accounts))?,
            data: ClaimInstructionData::try_from(data)?,
        })
    }
}

impl<'a> Claim<'a> {
    pub const DISCRIMINATOR: &'a u8 = &1;

    pub fn process(&mut self) -> ProgramResult {
        let Self { program_id, accounts, data } = self;
        let (root, bump) = {
            let distributor = Distributor::load(accounts.distributor, program_id)?;
            (distributor.root, distributor.bump)
        };

        // The root from the distributor, the claimant from the signer, the amount from
        // the instruction.
        let inputs = PublicInputs {
            root,
            claim: token_claim_verifier::Claim { claimant: *accounts.claimant.address().as_array(), amount: data.amount },
        };
        if !verify(&Proof::from_le_bytes(data.proof), inputs) {
            return Err(TokenClaimError::InvalidProof.into());
        }

        // The receipt, at ["claimed", distributor, claimant]: once it exists, this
        // address has claimed. It must sit at the canonical bump, so it's searched for.
        let (address, receipt_bump) = Address::find_program_address(
            &[CLAIMED_SEED, accounts.distributor.address().as_ref(), accounts.claimant.address().as_ref()],
            program_id,
        );
        if accounts.receipt.address() != &address {
            return Err(ProgramError::InvalidSeeds);
        }
        if accounts.receipt.owned_by(program_id) {
            return Err(ProgramError::AccountAlreadyInitialized);
        }
        let receipt_bump = [receipt_bump];
        let receipt_seeds = [
            Seed::from(CLAIMED_SEED),
            Seed::from(accounts.distributor.address().as_ref()),
            Seed::from(accounts.claimant.address().as_ref()),
            Seed::from(&receipt_bump),
        ];
        create(accounts.claimant, accounts.receipt, 0, program_id, &receipt_seeds)?;

        // Pay from the vault, signed by the distributor's seeds.
        let bump = [bump];
        let seeds = [Seed::from(DISTRIBUTOR_SEED), Seed::from(&root), Seed::from(&bump)];
        Transfer::new(accounts.vault, accounts.claimant_token, accounts.distributor, data.amount)
            .invoke_signed(&[Signer::from(&seeds)])
    }
}

```

`PublicInputs` is the circuit's public inputs by name, generated in the verifier crate: the
`root`, and a `Claim` with the claimant's 32-byte address and the amount. `verify` packs them into
the four field elements `xark inspect` printed, in its order, splitting the address into its two
halves as the circuit does, so the program never builds them by hand. The proof stays a reference
into the instruction data: a 256-byte copy on the stack, beside the verifier's own, overflows the
4 KiB frame a Solana program gets.

Each check closes a way to take tokens that aren't yours:

- **The claimant signs.** The claimant chooses the token account `to` that's paid, so without this
  anyone holding Bob's proof could claim Bob's tokens to their own account.
- **The distributor is one `initialize` made**: `Distributor::load` checks it's the program's, and
  of its size (a receipt is the program's too, but empty). Otherwise a claimant could pass an
  account holding the root of a list of their own.
- **The vault is the distributor's**, derived from the bump `initialize` stored. The token program
  would refuse any other vault too, since only this one's owner signs; the check fails it early,
  with `InvalidSeeds`.
- **The program assembles the public inputs.** The root comes from the distributor, the claimant
  from the signer, the amount from the instruction. A proof made for another list, another wallet
  or another amount fails `verify`, with `InvalidProof`. See
  [Where the public inputs come from](/docs/guides/how-verification-works#where-the-public-inputs-come-from).
- **The receipt is the claimant's PDA, at its canonical bump, and new.** It's derived from the
  distributor and the claimant's address, so a claimant can't pass a fresh account each time. The
  bump is the one `find_program_address` finds, not one the client sends, or the same claimant
  would have a receipt at each of the other bumps too. Once it exists, a second claim fails with
  `AccountAlreadyInitialized`.

The program needs no nullifier, because it knows who's claiming: the signer. And it can't
remember claims by the proof's bytes, since anyone holding a Groth16 proof can re-randomize it
into another valid proof of the same statement. The token program checks that `to` holds the
vault's mint. The transfer at the end is signed with the distributor's seeds
(`invoke_signed`): the program signing for the vault's owner.
</Step>

### Create accounts that can't be blocked

Last, the helper both instructions create accounts with, and the entrypoint's log. Create
`programs/token-claim/src/helpers.rs`:

```rust title="programs/token-claim/src/helpers.rs"
use pinocchio::{AccountView, Address, ProgramResult, cpi::{Seed, Signer}, sysvars::{Sysvar, rent::Rent}};
use pinocchio_system::instructions::{Allocate, Assign, CreateAccount, Transfer};

/// Create the PDA `account`, signed by its `seeds`: `space` bytes owned by `owner`,
/// paid by `payer`.
pub fn create(payer: &AccountView, account: &AccountView, space: usize, owner: &Address, seeds: &[Seed]) -> ProgramResult {
    let signer = [Signer::from(seeds)];
    let rent = Rent::get()?.try_minimum_balance(space)?;
    let held = account.lamports();
    if held == 0 {
        return CreateAccount { from: payer, to: account, lamports: rent, space: space as u64, owner }.invoke_signed(&signer);
    }
    // Anyone can send lamports to an address, and `CreateAccount` refuses one that
    // holds any: top it up, allocate and assign it instead.
    if held < rent {
        Transfer { from: payer, to: account, lamports: rent - held }.invoke()?;
    }
    if space > 0 {
        Allocate { account, space: space as u64 }.invoke_signed(&signer)?;
    }
    Assign { account, owner }.invoke_signed(&signer)
}

/// Write `message` to the program's logs. A build on your machine has none.
pub fn log(message: &str) {
    #[cfg(any(target_os = "solana", target_arch = "bpf"))]
    // SAFETY: the pointer and length are a valid `&str`'s.
    unsafe {
        pinocchio::syscalls::sol_log_(message.as_ptr(), message.len() as u64)
    };
    #[cfg(not(any(target_os = "solana", target_arch = "bpf")))]
    let _ = message;
}
```

A PDA's address is known in advance, and anyone can send lamports to any address. The system
program's `CreateAccount` refuses an address that holds lamports, so with `CreateAccount` alone, a
griefer could block Alice's claim forever by sending her receipt's address a lamport. `create`
tops such an account up, allocates it and assigns it to its owner instead.
</Step>

```ts title="tests/token-claim.test.ts"
/** The distributor and its vault for the list rooted at `root`: the program's PDAs. */
async function distributorOf(program: Address, root: Field) {
  const [distributor] = await getProgramDerivedAddress({ programAddress: program, seeds: ["distributor", root.toBytes()] });
  const [vault] = await getProgramDerivedAddress({ programAddress: program, seeds: ["vault", bytes(distributor)] });
  return { program, root, distributor, vault };
}
type Drop = Awaited<ReturnType<typeof distributorOf>>;

/** `initialize`: create the distributor, and fund its vault with `total` from `from`. */
const initialize = (d: Drop, authority: KeyPairSigner, mint: Address, from: Address, total: bigint): Instruction => ({
  programAddress: d.program,
  accounts: [signer(authority), writable(d.distributor), writable(d.vault), readonly(mint), writable(from), readonly(TOKEN_PROGRAM_ADDRESS), readonly(system)],
  data: new Uint8Array([0, ...d.root.toBytes(), ...u64le(total)]),
});

/** `claim`: `amount`, signed by `claimant`, paid to the token account `to`. */
async function claim(d: Drop, claimant: KeyPairSigner, to: Address, proof: Uint8Array, amount: bigint): Promise<Instruction> {
  const [receipt] = await getProgramDerivedAddress({ programAddress: d.program, seeds: ["claimed", bytes(d.distributor), bytes(claimant.address)] });
  return {
    programAddress: d.program,
    accounts: [signer(claimant), readonly(d.distributor), writable(d.vault), writable(receipt), writable(to), readonly(TOKEN_PROGRAM_ADDRESS), readonly(system)],
    data: new Uint8Array([1, ...proof, ...u64le(amount)]),
  };
}
```

## What you built

A distributor published one root for a list of three, and could have for a million. Each address
on it claimed its tokens once, with a proof of a path no transaction ever carried. The new ideas:

- **A Merkle tree in a circuit.** Each leaf is `Poseidon2(claimant.hi, claimant.lo, amount)`;
  `Private<Path>` holds an index and 20 siblings, and `require_eq(path.root(claim.leaf()), root)`,
  the whole circuit, proves the leaf is under the published root.
- **A builder written once.** `list()`, `xark-merkle`'s host `Tree`, builds the list in Rust;
  `Path::first`, `next`, `update` and `list_root` are host-only Rust in the circuit crate, and
  through `#[input] impl` the distributor's TypeScript calls them, so the tree it publishes is
  hashed exactly as the circuit's `merkle_root` hashes it.
- **Poseidon2 leaves and nodes**, as two different functions of it, at a fixed depth.
- **A receipt instead of a nullifier.** The claimant and the amount are public, so the program
  keys a receipt PDA on the signer's address.
- **An SPL vault** owned by a PDA, paid out by the program signing with its seeds.

What hiding the path buys: a claim is 256 bytes of proof and 8 of amount however deep the tree, the
program never hashes and has no Poseidon2 to keep in step with the circuit, and none of the
siblings, which are other people's leaves, ever goes onchain. What it doesn't hide: the claimant
and the amount. They're public inputs the program fills in from the signer and the instruction, so
anyone reading the chain sees who claimed how much.

The next tutorial hides them. Put 02's salted commitments in the leaves instead of addresses, and
the Merkle tree becomes a **shielded pool**: a deposit adds a commitment, a withdrawal proves it
knows the secrets behind one of the leaves without saying which, and a nullifier stops it from
withdrawing twice.

The program accepts any list from anyone. A real distributor also checks that its list has one
entry per address (a second entry for the same address can never be claimed), funds the vault
with at least the list's total, and adds a way to close the vault and recover what's unclaimed
after a deadline.

program that holds tokens needs a key from a ceremony. See
[The trusted setup](/docs/trust/trusted-setup).
</Callout>

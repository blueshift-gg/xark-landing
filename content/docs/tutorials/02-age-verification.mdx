---
title: "02 · Age verification"
description: Prove you're 18 or older today without revealing your birth date. Commitments, typed inputs and policies, and a proof bound to the wallet that signs.
---

In this tutorial you'll prove to a Solana program that you're 18 or older today, revealing
neither your birth date nor anything else about you. It's the range check from
[01 · Over 9000](/docs/tutorials/01-over-9000), with three things that make it hold up:

- a **commitment** an issuer publishes, so the birth date can't be made up;
- a **policy** the program builds from its own clock, so "today" can't be made up either;
- the **holder's wallet** as a public input, so no one else can submit the proof.

By the end you'll have the same pieces as in 01: a circuit and its tests, a TypeScript client, a
Solana program, and an end-to-end test that sends a proof to the program and sees it accepted for
the right wallet on the right day, and refused otherwise.

<Callout title="Prerequisites">
Everything from [01's prerequisites](/docs/tutorials/01-over-9000): stable Rust 1.89 or newer,
`xark-cli` 0.3, Node 22 or newer, and the Anza CLI for `cargo-build-sbf`. Nothing new. You don't
need 01's files, but this tutorial assumes you've done it and doesn't re-explain its commands.
</Callout>

<Step>
### Describe the inputs

A circuit's inputs can be structs. Replace `age-verification/src/lib.rs` with:

```rust title="age-verification/src/lib.rs"
use xark::prelude::*;

/// A calendar day from 1900 through 2100.
pub type Date = Days<1900, 2100>;

/// What an issuer attests about a holder.
#[input]
pub struct Identity {
    pub born: Date,
    /// The issuer's random secret: it hides the commitment.
    pub salt: Field,
}

#[input]
impl Identity {
    /// The issuer's commitment: all a verifier sees of the holder.
    pub fn commitment(&self) -> Field {
        xark_poseidon2::hash(self.to_fields())
    }
}
```

An issuer (a KYC provider, say) gives the holder an `Identity` and publishes only its commitment,
the Poseidon2 hash of its fields. The salt is what keeps the commitment from leaking the date:
there are only about 40,000 plausible birth dates, and without a salt anyone could hash them all
and find the match.

`Date` is one of xark's everyday input types. In the circuit it's a count of days since
1900-01-01, so dates compare as numbers; in tests it's a string like `"1990-01-01"`, and in
TypeScript a `Date`. See [Everyday types](/docs/reference/inputs#everyday-types).

Now append the verifier's side, the policy:

```rust title="age-verification/src/lib.rs"
/// What a verifier requires: born on or before `born_by`.
#[input]
pub struct Policy {
    pub born_by: Date,
}

#[input]
impl Policy {
    /// 18 or older on `today`.
    #[cfg(not(xark))]
    pub fn adult_on(today: impl Into<Date>) -> Policy {
        Policy {
            born_by: today.into().years_before(18),
        }
    }
}
```

`#[input]` on an `impl` exports its methods to the TypeScript client, so the issuer computes the
commitment, and the holder the policy, with this same Rust. `#[cfg(not(xark))]` leaves
`adult_on` out of the circuit build: the circuit never calls it; it only compares.
</Step>

<Step>
### Write the circuit and its tests

Append the circuit and three tests:

```rust title="age-verification/src/lib.rs"
#[circuit]
pub fn age_verification(
    id: Private<Identity>,
    commitment: Public<Field>,
    policy: Public<Policy>,
) {
    require_eq(id.commitment(), commitment);
    require(id.born <= policy.born_by);
}

#[cfg(test)]
mod tests {
    use super::*;

    fn holder(born: &str) -> Identity {
        Identity {
            born: born.into(),
            salt: Field::from_le_bytes(&[0x2a; 31]),
        }
    }

    fn check(id: Identity, today: &str) -> Result<(), xark::prover::ProveError> {
        age_verification(id, id.commitment(), Policy::adult_on(today))
    }

    #[test]
    fn an_adult_passes() {
        check(holder("1990-01-01"), "2026-10-22").unwrap();
        check(holder("2008-10-22"), "2026-10-22").unwrap(); // 18 today
    }

    #[test]
    fn a_minor_fails() {
        assert!(check(holder("2008-10-23"), "2026-10-22").is_err()); // 18 tomorrow
        // Born on 29 February: 18 on 1 March in a common year.
        assert!(check(holder("2008-02-29"), "2026-02-28").is_err());
        check(holder("2008-02-29"), "2026-03-01").unwrap();
    }

    #[test]
    fn another_identity_fails() {
        let id = holder("1990-01-01");
        let other = holder("1990-01-02").commitment();
        assert!(age_verification(id, other, Policy::adult_on("2026-10-22")).is_err());
    }
}
```

The first `require_eq` is the one that matters. In 01 the prover could pick any number. Here the
birth date has to be the one inside a commitment the issuer published, so the prover can't choose
a convenient one. The second line is 01's range check, against a date the verifier supplies.

The tests call the circuit's own Rust (`id.commitment()`, `Policy::adult_on`) to build their
inputs, as the client will.
</Step>

<Step>
### Bind the proof to the holder's wallet

So far a proof says that *someone* holding this credential is an adult. Anyone who saw it
onchain could submit it as their own. To stop that, make the holder's wallet a public input. A
Solana address is 32 bytes, which the circuit takes as `xark_hash::Hash`.

Add the import at the top of `src/lib.rs`:

```rust title="age-verification/src/lib.rs"
use xark_hash::Hash;
```

and give the circuit a fourth input:

```rust title="age-verification/src/lib.rs"
#[circuit]
pub fn age_verification(
    id: Private<Identity>,
    commitment: Public<Field>,
    policy: Public<Policy>,
    holder: Public<Hash>,
) {
    require_eq(id.commitment(), commitment);
    require(id.born <= policy.born_by);
}
```

In the tests, add a wallet after `use super::*;`:

```rust title="age-verification/src/lib.rs"
    const HOLDER: [u8; 32] = [7; 32];
```

and pass `HOLDER` as the last argument to both calls of `age_verification`:

```rust title="age-verification/src/lib.rs"
        age_verification(id, id.commitment(), Policy::adult_on(today), HOLDER)
```

```rust title="age-verification/src/lib.rs"
        assert!(age_verification(id, other, Policy::adult_on("2026-10-22"), HOLDER).is_err());
```

Run the tests again:

```console
$ xark test age-verification
xark building circuit `age-verification`
warning: unused variable: `holder`
...
error: public input `holder.hi` is declared but no constraint uses it
  = note: if only the verifier supplies it (a recipient, a nonce), say so with `bind(it)`: the proof then verifies only with the value it was made for. Otherwise use it in a constraint, or remove it from the signature
```

xark refuses the circuit. Groth16 only checks a public input through the constraints that use
it, so an input no constraint touches would verify with any value. Nothing needs to compute with
`holder`; it only has to be tied to the proof. That's what `bind` does. Add it as the circuit's
last line:

```rust title="age-verification/src/lib.rs"
    require(id.born <= policy.born_by);
    bind(holder);
}
```

[Constraints](/docs/reference/language#constraints).

```rust title="program/src/lib.rs"
#![cfg_attr(not(test), no_std)]

use age_verification_verifier::{Proof, verify};
use pinocchio::{
    AccountView, Address, ProgramResult,
    error::ProgramError,
    program_entrypoint,
    sysvars::{Sysvar, clock::Clock},
};

program_entrypoint!(process_instruction);
#[cfg(not(test))]
pinocchio::nostd_panic_handler!();
#[cfg(not(test))]
pinocchio::no_allocator!();

/// Accounts: the holder, a signer. Data: proof (256 B) ‖ commitment (32 B).
fn process_instruction(
    _program_id: &Address,
    accounts: &mut [AccountView],
    instruction_data: &[u8],
) -> ProgramResult {
    let Some((proof, commitment)) = instruction_data.split_first_chunk::<256>() else {
        return Err(ProgramError::InvalidInstructionData);
    };
    let commitment: [u8; 32] = commitment
        .try_into()
        .map_err(|_| ProgramError::InvalidInstructionData)?;
    let [holder, ..] = accounts else {
        return Err(ProgramError::NotEnoughAccountKeys);
    };
    if !holder.is_signer() {
        return Err(ProgramError::MissingRequiredSignature);
    }
    // The public inputs, in the circuit's order: commitment, policy.born_by,
    // holder.hi, holder.lo.
    let born_by = field(born_by(Clock::get()?.unix_timestamp));
    let [holder_hi, holder_lo] = halves(holder.address().as_array());
    let public_inputs = [commitment, born_by, holder_hi, holder_lo];
    if verify(&Proof::from_le_bytes(proof), &public_inputs) {
        Ok(())
    } else {
        Err(ProgramError::InvalidInstructionData)
    }
}

/// An address as the circuit's `Hash`: `[hi, lo]`, each 16-byte half read as a
/// big-endian integer, as 32-byte little-endian field elements.
fn halves(bytes: &[u8; 32]) -> [[u8; 32]; 2] {
    let half = |b: &[u8]| {
        let mut out = [0u8; 32];
        out[..16].copy_from_slice(b);
        out[..16].reverse();
        out
    };
    [half(&bytes[..16]), half(&bytes[16..])]
}

/// A `u32` as a 32-byte little-endian field element.
fn field(x: u32) -> [u8; 32] {
    let mut out = [0u8; 32];
    out[..4].copy_from_slice(&x.to_le_bytes());
    out
}
```

Unlike 01, the instruction data isn't the whole statement: the program only takes the proof and
the commitment from the transaction. A proof made for another day or another wallet then fails
`verify`. See [Where the public inputs come from](/docs/guides/how-verification-works#where-the-public-inputs-come-from).
</Step>

<Step>
### Compute the policy onchain

The program can't link xark, so it computes `Policy::adult_on(today).born_by` itself, as the
circuit's `Date` holds it: days since 1900-01-01. Append to `program/src/lib.rs`:

```rust title="program/src/lib.rs"
/// `Policy::adult_on(today).born_by` for the day holding the Unix time `unix`, as
/// the circuit's `Date` holds it: days since 1900-01-01. The same day 18 years
/// earlier, or the 28th for a 29 February that year doesn't have.
fn born_by(unix: i64) -> u32 {
    let (y, m, d) = civil_from_days(unix.div_euclid(86_400));
    let y = y - 18;
    let leap = (y % 4 == 0 && y % 100 != 0) || y % 400 == 0;
    let d = if m == 2 && d == 29 && !leap { 28 } else { d };
    (days_from_civil(y, m, d) - days_from_civil(1900, 1, 1)) as u32
}

/// The civil date of a day count from 1970-01-01: Howard Hinnant's
/// `civil_from_days` (http://howardhinnant.github.io/date_algorithms.html).
fn civil_from_days(z: i64) -> (i64, i64, i64) {
    let z = z + 719_468;
    let era = z.div_euclid(146_097);
    let doe = z - era * 146_097;
    let yoe = (doe - doe / 1_460 + doe / 36_524 - doe / 146_096) / 365;
    let doy = doe - (365 * yoe + yoe / 4 - yoe / 100);
    let mp = (5 * doy + 2) / 153;
    let day = doy - (153 * mp + 2) / 5 + 1;
    let month = if mp < 10 { mp + 3 } else { mp - 9 };
    (yoe + era * 400 + i64::from(month <= 2), month, day)
}

/// Its inverse: Hinnant's `days_from_civil`.
fn days_from_civil(y: i64, m: i64, d: i64) -> i64 {
    let y = if m <= 2 { y - 1 } else { y };
    let era = y.div_euclid(400);
    let yoe = y - era * 400;
    let doy = (153 * (if m > 2 { m - 3 } else { m + 9 }) + 2) / 5 + d - 1;
    let doe = yoe * 365 + yoe / 4 - yoe / 100 + doy;
    era * 146_097 + doe - 719_468
}

#[cfg(test)]
mod tests {

        let end = days_from_civil(2101, 1, 1) * 86_400;
        for unix in (start..end).step_by(86_400) {
```

```ts title="app/age-verification.test.ts"
// Send `instruction` in one transaction, paid by `payer`. Returns the compute
// units it used, or throws with the program's logs.
async function send(svm: LiteSVM, payer: KeyPairSigner, instruction: Instruction) {
  const tx = await pipe(
    createTransactionMessage({ version: 0 }),
    (m) => setTransactionMessageFeePayerSigner(payer, m),
    (m) => setTransactionMessageLifetimeUsingBlockhash({ blockhash: svm.latestBlockhash(), lastValidBlockHeight: 0n }, m),
    (m) => appendTransactionMessageInstruction(instruction, m),
    (m) => signTransactionMessageWithSigners(m),
  );
  const result = svm.sendTransaction(tx);
  svm.expireBlockhash();
  if (result instanceof FailedTransactionMetadata) {
    throw new Error(`transaction failed: ${result.err()}\n${result.meta().logs().join("\n")}`);
  }
  return result.computeUnitsConsumed();
}

// The program's instruction: signed by `holder`, with data proof ‖ commitment.
const verifyAge = (program: Address, holder: KeyPairSigner, proof: Uint8Array, commitment: Field) => ({
  programAddress: program,
  accounts: [{ address: holder.address, role: AccountRole.READONLY_SIGNER, signer: holder }],
  data: new Uint8Array([...proof, ...commitment.toBytes()]),
});

// Set the VM's clock to noon UTC on `day`.
function setDay(svm: LiteSVM, day: string) {
  const clock = svm.getClock();
  clock.unixTimestamp = BigInt(Date.parse(`${day}T12:00:00Z`) / 1000);
  svm.setClock(clock);
}
```

Finally, the test. The holder proves for today's policy and their own address, and the program
accepts the proof only from that wallet, for that commitment, on that day:

```ts title="app/age-verification.test.ts"
test("the program accepts the proof for its holder, today", async () => {
  const svm = new LiteSVM();
  const program = (await generateKeyPairSigner()).address;
  svm.addProgramFromFile(program, "../program/target/deploy/age_verification_program.so");
  const payer = await generateKeyPairSigner();
  svm.airdrop(payer.address, lamports(1_000_000_000n));
  setDay(svm, "2026-10-22");

  // The issuer's credential and its public commitment, and the holder's wallet.
  const id = credential("1990-01-01");
  const commitment = Identity.commitment(id);
  const holder = await generateKeyPairSigner();

  const policy = Policy.adultOn(new Date("2026-10-22"));
  const address = new Uint8Array(getAddressEncoder().encode(holder.address));
  const proof = prover.prove({ id, commitment, policy, holder: address }).toBytes();
  const units = await send(svm, payer, verifyAge(program, holder, proof, commitment));

  const copycat = await generateKeyPairSigner();

  // and tomorrow the program's policy has moved on.
  setDay(svm, "2026-10-23");

});
```

for another commitment, and the next day. A proof is for one UTC day: one that lands after
midnight UTC has to be made again.
</Step>

</Steps>

## What you built

A holder proved they're 18 or older to a Solana program, and the program learned only that: not
the birth date, and not who the holder is beyond their wallet. Three things made the range check
from 01 into an age gate:

- **A commitment.** `require_eq(id.commitment(), commitment)` ties the private date to one an
  issuer published, so the prover can't choose it.
- **A typed policy, from the program.** `Policy` is a public input the program builds from its
  `Clock`, so "today" is the chain's, not the prover's. `#[input]` structs and `Days` gave the
  circuit, the tests and the TypeScript client the same types, and `#[input] impl` gave the client
  the circuit's own `Identity.commitment` and `Policy.adultOn`.
- **A bound signer.** `bind(holder)` ties the proof to one wallet, which the program fills in from
  the transaction's signer.

A proof guarantees consistency, not honesty. It shows the date inside the commitment is old
enough; it says nothing about whether the commitment is true. This program accepts any
commitment, so anyone could commit to a 1900 birth date and pass. A real one checks the commitment
against a registry its trusted issuers sign, or has the circuit verify the issuer's signature with
a [signature gadget](/docs/gadgets/signatures). The [Inputs reference](/docs/reference/inputs)
opens with xark's `zkyc` example: this circuit grown into a full KYC policy, with nationality, net
worth and document expiry.

<Callout type="warn" title="Before you deploy">
`xark setup` made a single-party key: sound unless whoever ran it kept its randomness. A program
that guards anything real needs a key from a ceremony. See
[The trusted setup](/docs/trust/trusted-setup).
</Callout>

[02-age-verification](https://github.com/blueshift-gg/xark-examples/tree/main/02-age-verification)
in xark-examples.

A **gadget** in xark is just a Rust crate that lowers to the same primitive constraints as
hand-written circuit code. There is no per-gadget backend opcode and no separate circuit
language: you add a dependency with `cargo`, call a function inside your `#[circuit]`, and xark
builds it into the circuit with everything else — loops unrolled, calls inlined.

That design makes it easy to add, extend, and distribute new gadgets for xark — it is all just
ordinary Rust.

## Using a gadget

Add the gadget crate next to `xark`:

```toml
# Cargo.toml
[dependencies]
xark = "0.3"
xark-poseidon = "0.3"
```

```rust
use xark_poseidon::prelude::*;

#[circuit]
pub fn poseidon(a: Private<Field>, b: Private<Field>, out: Public<Field>) {
    require_eq(hash2(a, b), out);
}
```

A gadget's `prelude` brings in two things at once: the gadget's own functions and types, and xark's
prelude. The building-block crates (`xark-bits`, `xark-hash`, `xark-curve`) are imported by path
instead — `use xark_bits::{and32, xor32};`, `use xark_hash::Hash;`.

One gotcha: a glob import is **shadowed by a local definition of the same name**. If your entry
function is itself called `sha256`, then `sha256(msg)` inside the circuit calls *your* function,
not the gadget's — so qualify the gadget call as `xark_sha256::sha256(msg)`, as the
[example circuits](https://github.com/blueshift-gg/xark/tree/master/examples) do.

<Callout title="BN254 is the only field">
Gadgets are written for the BN254 scalar field, the field xark's keys and proofs use. Their
constants are BN254 field elements, so they aren't valid in a circuit built with
`xark build --field <F>`.
</Callout>

## What a gadget costs

Only `variable * variable` emits an R1CS gate. Everything else folds away, and this is what makes
the gadgets affordable:

- **Field constants are free.** Round constants, MDS matrices, and multiplication by a constant
  fold into linear combinations; Poseidon's cost is its `x^5` S-boxes.
- **Re-wiring is free.** Rotations, shifts, and lane permutations in the bit-oriented hashes
  (SHA-256's `Σ`/`σ`, Keccak's ρ/π, AES ShiftRows) move bits between array slots and emit nothing.
- **Booleanity is not free.** A range check to `N` bits costs about `N` constraints, and a
  bitwise operation on witness bits costs about a gate per bit.
- **Decompositions are cached per `(value, width)`.** Range-checking the same value twice — or
  range-checking it once and then comparing it — pays only once.

Each gadget page quotes measured counts for its example circuits. For your own circuit, run
`xark inspect <crate>` for the totals and `xark profile <crate>` to attribute each constraint to its
source line and function chain.

## Inputs and the host

A `#[circuit]` signature may use a gadget's own types. Each has a natural form on the host — in
tests, `--inputs`, and the TypeScript client — and a field-element form in the circuit:

- A **byte array** `[u8; N]` is `N` field elements, each range-checked to a byte.
- A **signature gadget's** `Point`, `Signature` and `Scalar` are bytes on the host — a secp256k1
  `Point` is the 64-byte `x ‖ y` (SEC1 without the `0x04` tag) — and limbs in the circuit.
- A **`Hash`** is a plain `[u8; 32]` on the host and two field elements in the circuit, so a
  `Public<Hash>` costs two public inputs instead of 256.

`xark setup` writes `inputs.example.json` with every input in its natural form, to fill in:

```sh
xark setup my-circuit
# fill in my-circuit/target/xark/my-circuit/inputs.example.json, then:
xark prove my-circuit --inputs my-circuit/target/xark/my-circuit/inputs.example.json
```

<Callout type="info" title="Start from a worked example">
Each gadget has one or more runnable circuits under
[`examples/`](https://github.com/blueshift-gg/xark/tree/master/examples) — `sha256`, `poseidon`,
`secp256k1_ecdsa`, `ed25519`, `merkle`, `aes_gcm`, `grumpkin_ivc`, and the rest — with tests that
show each gadget's host input form in practice. `xark test examples/<name>` runs any of them.
</Callout>

## Writing your own

Because a gadget is library code, the test for "can this be a gadget?" is the
[supported subset](/docs/reference/supported-subset): fixed-size arrays, loops whose length the
circuit's shape fixes, `Field` and integer arithmetic, and calls to other gadgets. Hashes and
curves are not special-cased; they are just code that respects those rules. Put `#[input]` on a
gadget's types and they work as circuit inputs, and on their `impl`s to bring those functions to
every circuit's [TypeScript client](/docs/guides/typescript-clients).

To prove something in zero knowledge, you first have to express it as a **circuit**. This is the
part that trips people up, so let's make it concrete.

## A circuit is a set of constraints, not a program

You're used to code that *runs* — it takes inputs and produces outputs step by step. A ZK circuit
is different: it's a list of **constraints** (equations) that a set of values must *satisfy*
simultaneously. The prover finds values that satisfy them; the proof attests that such values
exist and that the prover knows them.

In xark it is regular Rust:

```rust
use xark::prelude::*;

#[circuit]
pub fn over_9000(power_level: Private<u64>) {
    require(power_level > 9000);   // a constraint: this must hold
}
```

`Private<T>` marks a secret witness input; `Public<T>` marks a value the verifier receives.
`require` turns the comparison into constraints compiled into the circuit — not a check the prover
can skip at runtime. The proof exists only if every constraint holds for the prover's secret
witness.

## Everything becomes arithmetic over a finite field

Under the hood, constraints are polynomial equations over a **finite field** — integers mod a big
prime `p` (for BN254, a specific 254-bit prime). Addition and multiplication wrap around `p`.
That's the native "type" of a circuit: a *field element*. xark's `Field` is exactly this.

Two consequences you'll feel:

- **Comparisons and bit operations aren't free.** `a > b`, `a & b`, "is this 8 bits?" all have to be
  *built* out of field arithmetic. That's what a **range proof** is — proving a value fits in N bits
  by decomposing it into bits and constraining each. The `u64` input above makes xark decompose
  `power_level` into 64 constrained bits, so `> 9000` compares integers.
  ([Example 01](/examples) is the minimal case.)
- **Hashes are chosen for the field.** Poseidon is popular in ZK precisely because it's cheap in
  field arithmetic — far cheaper than SHA-256 inside a circuit. That's why our commitments and
  Merkle trees use Poseidon2.

## Witness = a satisfying assignment

The **witness** is the full set of values (private + public + all the intermediates) that satisfies
every constraint. `xark prove` computes it from your inputs (`--inputs`). If your inputs *can't*
satisfy the circuit (e.g. `power_level = 9000` with a constraint requiring it to be strictly greater
than `9000`), witness generation fails — there's nothing to prove — and xark names the `require`
that fails.

## Rust → wasm → R1CS → proof

```
Rust source
   │  stable rustc compiles it for wasm32
   ▼
wasm module
   │  xark runs it with the witness values kept symbolic
   ▼
xark-IR         a small circuit intermediate representation
   │  xark lowers it to…
   ▼
R1CS            Rank-1 Constraint System — the constraint form Groth16 proves over
   │  xark setup + prove
   ▼
proof
```

There is no separate frontend language: **the circuit is ordinary Rust**, compiled by your stable
`rustc`. xark owns everything after the wasm (xark-IR → R1CS → Groth16 → on-chain verifier). It
accepts a subset of Rust and *rejects* anything it can't prove soundly, at its source line — that
rejection is a safety feature, not a limitation to route around.

## Circuit cost is real

Each operation adds constraints, and constraints cost proving time and memory. A Poseidon2 hash
of five field elements is about 700 constraints, a SHA-256 of three bytes about 16,000, and an
in-circuit secp256k1 ECDSA verify about 227,000. Part of designing a good ZK app is keeping the
circuit small: `xark inspect` gives the totals, and `xark profile` attributes every constraint to
a line of your Rust.

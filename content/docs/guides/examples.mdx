The [xark-examples](https://github.com/blueshift-gg/xark-examples) repo is a difficulty ladder: six
examples that tell one story, each introducing one new idea, and every one is built, proved, and
verified end-to-end inside an in-process Solana VM ([LiteSVM](https://github.com/LiteSVM/litesvm): no
validator, no network). Over 9000 teaches [range proofs](/docs/learn-zk/range-proofs); zKYC puts them
to work beside a salted commitment and an allow-list; Token claim brings Merkle trees into the
circuit; Shielded pool combines Merkle trees with commitments; Anonymous voting scopes a nullifier
to a poll and range-proves the choice; and Shielded transfer adds range proofs on amounts, for
private payments of any amount. Read them in order, or build each one yourself,
step by step, in the [tutorials](/docs/tutorials/01-over-9000).

## The pattern they share

Every example is the same loop from the [Quickstart](/docs/quickstart): a Rust circuit, `xark`
turning it into a proof and a verifier crate, and a small Solana program that calls that crate's
`verify`. The two shielded examples add one trick worth its own study — **the chain
never hashes.** All Poseidon2 hashing happens inside the circuit; it proves that a new Merkle root correctly
extends the old one, so the onchain program only stores roots and verifies proofs. Circuit and chain
agree by construction instead of by carefully matching two Poseidon2 implementations.

To run one, `npm ci` at the repo's root, then `npm run build` in `01-over-9000/` takes it from circuit
to a deployable `.so`, and `npm test` proves and verifies it; the repo's `RUNBOOK.md` has the full
toolchain and devnet deployment.

<Callout type="warn">
The examples are reference implementations for learning — unaudited, not for production. The shielded
ones especially are educational; privacy tooling carries real legal weight depending on your
jurisdiction.
</Callout>

Every circuit parameter's type implements `xark::Input`, which says how its value maps to field
elements and how clients see it. Integers, `bool`, `Field`, arrays and tuples implement it already;
this page covers the rest.

## `#[input]` structs

Group inputs into a struct with `#[input]`:

```rust
#[input]
pub struct Identity { document: Text, born: Days<1900, 2100>, nationality: Choice<Country>, net_worth: u64, expires: Days<1900, 2100>, salt: Field }

/// A verifier's rules, a public input: one circuit serves every policy.
#[input]
pub struct Policy { today: Days<1900, 2100>, born_by: Days<1900, 2100>, min_net_worth: u64, allowed: Bitfield<Country> }

#[circuit]
fn zkyc(id: Private<Identity>, commitment: Public<Field>, policy: Public<Policy>) {
    require_eq(id.commitment(), commitment);
    require(id.born <= policy.born_by);
    require(id.net_worth >= policy.min_net_worth);
    require(id.expires >= policy.today);
    id.nationality.require_in(policy.allowed);
}
```

`examples/zkyc` is this circuit in full. `#[input]` also derives `Clone`, `Copy` and `Debug` unless
the type lists them; `#[input(no_derive)]` is for a type with its own. Fields may be gadget types
too, and `to_fields()` gives a value's field elements, to hash it in one call.

### Packing

An `#[input]` struct's narrow fields are packed: consecutive integers, flags, days and enum values
share one field element (up to 253 bits) in declaration order, so `Identity` above is 3 field
elements and `Policy` 2 public inputs. Keep narrow fields together, and mark a field `#[unpacked]`
to give it its own.

## Everyday types

Each is one field element wide, with a natural form in tests, `--inputs`, and the TypeScript
client.

- `Days<FROM, TO>`: a day from the start of year `FROM` to the end of `TO` (UTC), in the circuit
  its day count, just wide enough for the range (`Days<1900, 2100>` is 17 bits). It's
  `"1990-01-01"` in Rust and `--inputs` and a JS `Date` in TypeScript, and any moment of a day is
  that day. `Time<UNIT, FROM, TO>` is the same in other steps (`Time<MINUTE, 2020, 2060>`).
- `Timestamp`: any moment, as Unix seconds (an `i64`, as Solana's `Clock` and a JS `Date` hold
  it), compared as a signed 64-bit integer.
- `Text`: a short string, up to 31 bytes (a document number, a name).
- `Choice<E>` and `Bitfield<E>`: one variant of an enum, or a set of them, such as a nationality
  and the allowed countries. Any fieldless enum with `#[input]` works; `xark` ships ISO 3166
  `Country`.

`Choice` and `Bitfield` work together: `choice == Country::US`, `require_in`, `require_one_of`,
`contains`. A `bool` input is one field element, checked to be 0 or 1.

## Passing inputs

| Where | How |
| --- | --- |
| A test | the validator `#[circuit]` generates, e.g. `zkyc(id, commitment, policy)`; each argument takes whatever converts to it |
| Rust | the generated `<Fn>Inputs` struct, for `xark::prover::circuit(..).check(..)` and `.prove(..)`; its `to_json()` is the `--inputs` form |
| The CLI | `xark prove --inputs`, inline JSON or a file; names as declared (`net_worth`) or camelCase (`netWorth`) |
| TypeScript | a [generated client](/docs/guides/typescript-clients), with a type per input |

`xark setup` writes `inputs.example.json`, every input in its natural form, to fill in.

A `Field` takes an integer, a decimal or `0x`-hex string, or (in Rust) an `ark_bn254::Fr`. The
TypeScript client and `@blueshift-gg/xark` reject a value at or above the field's modulus rather
than reduce it, since it would prove a different number.

## Your own input types

A type `#[input]` doesn't cover implements `Input` by hand, in one impl that serves the circuit and
the host alike:

```rust
impl Input for Hash {
    const TYPE: Type = Type::Named(
        &Type::named("Hash", Layout::fields(&[Member::new("hi", Type::Field), Member::new("lo", Type::Field)]))
            .encoded(Encoding::Bytes(Bytes::Split(&[16, 16]))), // clients give its 32 bytes
    );
    fn read(r: &mut Reader) -> Self { Hash { hi: r.field(), lo: r.field() } }
    fn write(&self, w: &mut Writer) { w.field(self.hi); w.field(self.lo) }
}
```

A `TYPE` is built from the standard types — field, `uN`, bytes, number, date, text, choice, set,
arrays, tuples, structs — and those are what client generators map, so a client never needs to know
a circuit's own types.

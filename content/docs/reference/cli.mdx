`xark` compiles a circuit written in Rust into R1CS and proves and verifies it with Arkworks
Groth16 over BN254. It installs as **two** binaries: `xark` (the CLI, stable Rust) and
`xark-rustc` (the `rustc_driver` shim `xark build` runs to extract MIR, pinned nightly).

Run any command inside a circuit crate (a directory with a `Cargo.toml`) and every path is
inferred from the crate's `target/xark/`. Every flag below can override an inferred path.

## `xark init <name>`

Scaffold a starter circuit crate, pre-wired for `rust-analyzer` (so unsupported constructs
surface inline on save via `xark check`). With no name, initializes the current directory.

```sh
xark init my-circuit          # or: xark new my-circuit
```

Writes `Cargo.toml`, `src/lib.rs`, `rust-analyzer.toml`, and `.vscode/settings.json`.

## `xark build <crate-dir>`

Compile a circuit crate — rustc-MIR → xark-IR → R1CS — into `target/xark/`.

```sh
xark build examples/cube [--out DIR] [--field bn254] [--emit-json]
```

- `--out <DIR>` — output directory (default `<crate>/target/xark/<pkg-name>/`).
- `--field <F>` — the field (default `bn254`).
- `--emit-json` — also write the human-readable `circuit.json`. Off by default: `prove`/`check`
  load the compact `circuit.xbc`, so a normal build skips the (large, on big circuits) JSON
  serialization. `r1cs.json` is always written.

## `xark check <crate-dir>`

Validate a circuit crate *without emitting artifacts*, reporting subset rejections as real
`rustc` diagnostics with source spans. Great for editors / CI.

```sh
xark check examples/cube [--message-format=json]
xark check examples/cube --inputs '{"secret": 3, "result": 27}'
```

- `--message-format json` — machine-readable diagnostics, the shape `rust-analyzer`'s
  `check.overrideCommand` consumes.
- `--inputs` — opts into the witness-based soundness check: xark builds the circuit, solves the
  witness, and reports any derived variable the constraints fail to pin.

## `xark test <crate-dir>`

Build the circuit (so `target/xark/` artifacts exist), then run its `cargo test` circuit tests
in `--release`. Extra arguments after `--` forward verbatim to `cargo test`.

```sh
xark test examples/cube
xark test examples/cube -- --nocapture
```

## `xark setup`

Generate the Groth16 proving and verifying keys.

```sh
# dev keys (forgeable — demos only)
xark setup examples/cube

# production: phase-2 from a .ptau transcript
xark setup examples/cube --ptau-file powersOfTau.ptau
```

- `--insecure-dev-mode` — run setup with locally generated randomness. **Forgeable** — never
  ship a key made this way.
- `--ptau-file <PATH>` — the phase-1 powers-of-tau transcript (auto-detected under
  `target/xark/`, `ptau/`, or the crate root if present). Mutually exclusive with
  `--insecure-dev-mode`.
- `--phase2-seed <HEX>` — 32-byte hex seed for the `(γ, δ)` derivation.
- `--out <DIR>` — output directory (default `target/xark/<name>`).
- `--cache` — also write the minimized R1CS (`r1cs.min.wcz`) next to the keys, so a later
  `xark prove` reloads it instead of re-deriving it (skips the minimize + validate, ~25s on a
  multi-million-constraint circuit). Best for the produce-many-proofs flow; the cache can be
  hundreds of MB.
- `--uncompressed` — write the proving key uncompressed (2× on disk) so `prove` skips per-point
  decompression on load — a large prove-time win. `xark prove` auto-detects either format.
- `--deterministic-rng <SEED>` — reproducible randomness for regenerating committed test fixtures
  **only**; trivializes the Groth16 trapdoor. Requires `--insecure-dev-mode`.

## `xark prove`

Solve the witness from `--inputs` and produce a Groth16 proof (self-verified before returning).

```sh
xark prove examples/cube --inputs '{"secret": 3, "result": 27}'
```

- `--inputs <JSON|FILE>` — circuit inputs as inline JSON `{"name": value, …}` or a path to an
  input file. Array elements use the flat names `xark inspect` prints (e.g. `path[0]`).
- `--proving-key`, `--r1cs`, `--circuit`, `--out` — override inferred paths.
- `--cache` — write (on a miss) the minimized `r1cs.min.wcz` so subsequent proves against the same
  key skip the minimize + validate. A current cache is always used regardless of the flag.
- `--stream-pk` — stream the proving key from disk instead of loading it fully into RAM; the
  Groth16 MSMs read it in chunks, so prove peaks at the witness + `h`-poly rather than also
  holding the key. The proof is identical (still self-verified).

Writes `proof.bin` and `public_inputs.bin`, plus snarkjs-compatible `snarkjs-proof.json` and
`snarkjs-public.json`, under `target/xark/<name>/`.

## `xark verify`

Verify a proof against its public inputs.

```sh
xark verify examples/cube
# Proof verified: true
```

Prints `Proof verified: true` or `false`; exits non-zero when the proof does not verify.

## `xark export`

Export a self-contained Solana verifier crate with the verifying key baked in.

```sh
xark export examples/cube --crate-name my-verifier
```

- `--crate-name <NAME>` — the generated crate's package name (default `verifier`).
- `--allow-insecure` — emit a verifier for a key whose `metadata.json` is **not**
  `production_safe`. Without it, `export` refuses a dev-mode or otherwise unsafe key.

## `xark inspect <crate-dir>`

Print statistics about a built circuit — variable counts by visibility, the constraint count,
and the **public-input count and order**.

```sh
xark inspect examples/cube [--json]
```

- `--json` — machine-readable output instead of the human report.

## `xark ceremony`

Run a phase-2 MPC trusted setup so the keys don't depend on any single party.

```sh
xark ceremony init --r1cs examples/cube/target/xark/cube/r1cs.json \
  --ptau-file powersOfTau.ptau --out ./ceremony
xark ceremony contribute --ceremony-dir ./ceremony --label "alice"
xark ceremony verify --ceremony-dir ./ceremony
xark ceremony finalize --ceremony-dir ./ceremony
```

- `init` — seed the ceremony from a `.ptau` transcript and the circuit's `r1cs.json`.
- `contribute` — apply one contributor's randomness in place (writes a `contribution_NNNN.json`).
- `verify` — verify the full contribution chain.
- `finalize` — mark the chain finished and write the final `metadata.json`.

Full walkthrough in [The trusted setup](/docs/trust/trusted-setup).

## Also

- `xark doctor` — check your toolchain is set up to build and prove circuits.
- `xark profile <crate-dir>` — attribute each constraint to its source line, function chain, and
  kind (writes `profile.json`).
- `xark client` — scaffold a TypeScript client (snarkjs verify + on-chain calldata).
- `xark clean` — remove every `target/xark/` under the current directory.
- `xark completions bash|zsh|fish|elvish` — print a shell completion script.

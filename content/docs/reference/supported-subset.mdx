title: The Rust subset xark accepts
description: What lowers to a circuit — and what's rejected, before you spend a setup.
---

xark compiles a **restricted subset of Rust** to an arithmetic circuit. You write ordinary Rust
and `rustc` type-checks it, but only constructs with a well-defined *fixed arithmetic* meaning
are accepted — everything else is rejected at build time with a diagnostic pointing at the source
line. It never emits a proof for a construct it doesn't understand.

## The mental model

A circuit is a **fixed system of arithmetic constraints over a finite field**. xark builds it by
compiling your crate to wasm with stable `rustc` and *running* it with every witness value kept
symbolic: constants, loop counters and indices simply execute (that is the unrolling and
inlining), and every operation on a witness becomes constraints. Rule of thumb:

> **Everything that decides the *shape* of the circuit — loop lengths, array sizes, which memory
> is touched — must be known at compile time, or provably take only a few values. Witness
> *values* may flow anywhere, including into `if`s.**

```rust
use xark::prelude::*;

/// Prove knowledge of a cube root: `secret^3 == result`.
#[circuit]
pub fn cube(secret: Private<Field>, result: Public<Field>) {
    require_eq(secret.pow(3), result);
}
```

## Supported

- **Types:** `Field`; `u8`..`u128` and `i8`..`i128`; `bool`; fixed-size arrays (nested too);
  tuples and structs of these. A circuit parameter is any `Input` type: these, `#[input]`
  structs, the [everyday types](/docs/reference/inputs), and gadget types. Integer and `bool`
  inputs are range-checked on entry.
- **`Field` arithmetic:** `+`, `-`, `*`, `/`, unary `-`, compound assignment (`+=`, …), and
  `.pow(n)` for a **constant** `n`. Multiplication by a constant is free; only `var * var` emits
  a gate. `a == b` / `a != b` give a circuit `bool`. Ordering needs a width — see
  [`Field`](/docs/reference/language#field).
- **Native integers on witnesses:** comparisons (signed too), wrapping and checked `+ - *`, `/` and
  `%` (by a witness too), bitwise operations, shifts (by a witness amount too), and `as` casts —
  widening is free, narrowing truncates, as in Rust.
- **Control flow:** `if` and `match` on anything (see below); loops with a constant bound, or a
  witness bound small enough that the loop provably ends (e.g. `0..(x & 3)`); iterators and
  adapters over arrays and constant ranges; `assert!` and overflow and bounds checks on witnesses,
  each of which becomes a constraint.
- **Memory:** `&mut` borrows, slices, `copy_from_slice`, nested-array rows. An index that depends
  on a witness works when it can take at most 1024 values (`t[(x & 7) as usize]`,
  `t[x as u8 as usize]`, a `match` lookup table): it becomes a select over every possible slot.
- **Functions:** ordinary calls, including across crates — **gadgets are just Rust libraries** —
  plus generics, trait objects, function pointers and recursion, as long as the call target and
  depth don't depend on a witness.
- **Bits:** `Field::to_bits::<N>()` / `from_bits::<N>()` and the gadget crates, with **constant**
  widths.

## Branches on witness values

An `if` (or `match`) whose condition depends on a witness runs **both** arms and selects the
results. What an arm *requires* binds only when that arm is taken:

- A requirement inside an arm (`require_eq`, `assert!`, checked arithmetic, a range check) holds
  only when the arm is taken; in the untaken arm it is vacuous. A check you need unconditionally
  belongs *before* the `if`.
- An arm that can only panic (an `assert!` that fails, `/ 0`, an out-of-bounds index) is treated
  as impossible: the circuit requires the condition to go the other way. If both arms panic, the
  inputs are rejected.
- A loop whose exit depends on a witness and isn't provably short is refused at build time
  ("a loop whose exit depends on a witness value can't be unrolled").

## Not supported — and what to do instead

| You wrote | Why it's rejected | Do this instead |
|---|---|---|
| `while i < n` / `for i in 0..n` with `n` an unbounded witness | the loop length would depend on the witness | bound it with a constant (`for i in 0..MAX { if i < n { … } }`) |
| `arr[i]` with `i` a wide witness (a `u32`, a `Field`) | a select over more than 1024 slots | narrow the index (`(i & 7) as usize`), or select by hand |
| `let n = read_len(); [Field; n]` | array length must be constant | use a `const` / const-generic `N` |
| `#[circuit] fn c<const N: usize>(xs: Private<[Field; N]>)` | the entry is built once, with fixed sizes | a `const N` for the parameter, or a generic helper called with a fixed `N` |
| calling through a fn pointer / trait object chosen by a witness | the call target would depend on the witness | branch on the witness and call each function directly |
| `hash2(k, 0)` where the parameter is a `Field` | Rust never turns a literal into a `Field` argument (`x * 2`, `2 * x`, `x == 0` do work) | `hash2(k, 0.into())` or `Field::from(0)` |
| `x as u8` on a `Field` | `Field` isn't a primitive integer | `Field::to_bits::<N>()` and recombine, or keep values as `uN` |
| a memory fill or copy whose size depends on a witness | the memory layout would depend on the witness | use fixed-size buffers |
| `f32` / `f64` arithmetic on a witness | floats only run on constants | fixed-point integers or `Field` |
| two `#[circuit]` functions in one crate | a crate builds one circuit | one crate per circuit (workspace members work), sharing plain functions |

If you hit a rejection not covered here, the diagnostic names the exact construct and source line
— that message is the source of truth.

<Callout title="Check as you write">
`xark check <crate-dir>` reports every rejection as a compiler diagnostic with a source span —
live in your editor via `rust-analyzer` (a crate `xark init` made is already set up), or in CI with
`--message-format=json`. See [the CLI](/docs/reference/cli#xark-check-crate-dir).
</Callout>

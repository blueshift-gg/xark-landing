title: The Rust subset xark accepts
description: What lowers to a circuit — and what's rejected, before you spend a setup.
---

xark compiles a **restricted subset of Rust** to an arithmetic circuit. You write ordinary Rust
and `rustc` type-checks it, but only constructs with a well-defined *fixed arithmetic* meaning
are accepted — everything else is rejected at build time as a real `rustc` diagnostic pointing
at the source span. It never emits an unsound proof for a construct it doesn't understand.

## The mental model

A circuit is a **fixed system of arithmetic constraints over a finite field**, decided entirely
at compile time. It has no runtime: no value-dependent control flow, no data-dependent memory
access, no I/O. Rule of thumb:

> **Everything that decides the *shape* of the circuit — loop lengths, array indices, branch
> conditions, array sizes — must be a compile-time constant. Only `Field` *values* may depend on
> the inputs.**

`Field` is the field-element type (BN254 scalar). `Private<Field>`/`Public<Field>` mark input
visibility. `require_eq(a, b)` emits an equality **constraint** (it does *not* return a native
`bool`).

```rust
#![no_std]
use xark::prelude::*;

/// Prove knowledge of a cube root: `secret^3 == result`.
pub fn circuit(secret: Private<Field>, result: Public<Field>) {
    require_eq(secret.pow(3), result);
}
```

## Supported

- **Types:** `Field`; fixed-size arrays `[Field; N]` (nested too); tuples and plain structs of
  `Field`, with **constant** array lengths.
- **`Field` arithmetic:** `+`, `-`, `*`, `/`, unary `-`, and exponentiation via `x.pow(n)`.
  Multiplication by a constant is free (folds into a linear combination); only `var * var`
  emits a gate.
- **Constants & host integers:** integer literals and `usize`/`u*` values for loop bounds,
  indices, widths — as long as they're compile-time constants.
- **Control flow, compile-time only:** `if cond { … } else { … }` where `cond` is constant;
  `while i < N` / `for i in 0..N` where `N` is constant (loops are fully **unrolled**).
- **Functions:** ordinary function calls, including across crates — **gadgets are just Rust
  libraries** (`xark-sha256`, `xark-poseidon`, …). They're inlined. See [Gadgets](/docs/gadgets).
- **Bit / integer gadgets:** `Field::to_bits::<N>()` / `from_bits::<N>()`, comparisons and shifts
  against a native-integer operand, and the gadget crates, all with **constant** widths (a shift
  amount must be a compile-time constant).

## Not supported — and what to do instead

| You wrote | Why it's rejected | Do this instead |
|---|---|---|
| `a += b`, `a -= b`, `a *= b` | compound assignment on `Field` isn't modeled | `a = a + b` |
| `for x in slice` / iterators | iterator desugaring isn't a circuit operation | `for i in 0..N { let x = arr[i]; }` |
| `while cond` on a `Field`-derived `cond` | witness-dependent control flow — the loop length would depend on inputs | make the bound a constant |
| `if secret_field == 0 { … }` | branches can't depend on a witness value | compute both sides and **mux**: `b + cond·(a − b)` with a boolean `cond` |
| `arr[i]` where `i` is a `Field`/input | witness-dependent indexing can't be lowered | use a constant or loop-counter index; for a data-dependent choice, mux |
| `let n = read_len(); [Field; n]` | array length must be constant | use a `const` / const-generic `N` |
| `&mut x` on a `Field` | a mutable borrow of a `Field` isn't supported | restructure to `x = …` (SSA-style) |
| `foo(a)` via a trait object / fn pointer | indirect / dynamic calls aren't supported | call the function directly (it gets inlined) |
| a function that calls itself | recursion isn't supported (no runtime stack) | unroll to a fixed depth, or use a loop with a constant bound |
| `a == b` as a *statement* | `==` returns a `{0,1}` **wire**, not a constraint — a bare comparison constrains nothing | `require_eq(a, b)` |
| `a != b` as a *statement* | same: it returns a wire | `require_ne(a, b)` |
| reading a whole inner array out of a nested one (`grid[i]` as a value) | only *scalar* nested access is modeled | rebuild element-by-element: `for j in 0..M { row[j] = grid[i][j]; }` |
| `x as u8` on a `Field` | only compile-time integer casts are supported | keep field values as `Field`; use bit gadgets for byte views |

If you hit a rejection not covered here, the diagnostic names the exact construct and source
line — that message is the source of truth.

## Equality is a constraint; ordering needs a width

`Field == Field` and `Field != Field` return a `{0,1}` field *wire* — a circuit value, not a
host `bool` — so a bare `a == b` statement constrains nothing. To pin the values, use the
constraint `require_eq(a, b)` (or `require_ne(a, b)`). Equality is exact at any size, so it needs
no range check: it costs a couple of constraints rather than an `N`-bit decomposition.

Ordering is different. A `Field` is a residue mod `p`, not an integer of a fixed width, so "`a` is
less than `b`" only means something once you say how many bits the values occupy. A comparison is
therefore **explicit about its width** and range-checks its witness operand(s) to `< 2ᴺ` before
comparing. There is no safe default width, so it has to come from one of two places:

- **Against a literal**, the literal's type supplies it: in `x < 100u32`, the `u32` says "treat `x`
  as a 32-bit value and compare it with 100". `>`, `<=`, `>=` work the same way.
- **Between two witnesses**, no literal carries a width, so you spell it out: `a.lt::<32>(b)`
  range-checks **both** operands. `gt`, `le`, `ge` have the same shape.

A bare `Field < Field` is deliberately **not** provided — a silent default (32 bits, say) would be
a footgun for 64-bit values — and `N` must stay `≤ 252`.

Like equality, a comparison yields a `{0,1}` **wire**: constrain it with `require(x < 100u32)`, or
use it in a mux.

<Callout title="Check as you write">
`xark check <crate-dir>` surfaces every rejection as a `rustc` diagnostic with a source span —
live in your editor via `rust-analyzer`, or in CI with `--message-format=json`. A violation looks
like:

```text
error: witness-dependent control flow is not supported
 --> src/lib.rs:7:5
note: branch conditions must be compile-time constants (e.g. loop bounds)
```
</Callout>

## Testing a circuit

Circuit crates are tested with **`xark test <crate-dir>`**, not bare `cargo test`: it builds the
`target/xark/` artifacts first, then runs the crate's tests, which load the built circuit and check
the witness solves. A rejecting test asserts the solve is `Err`. For a one-off end-to-end run,
`xark build <crate-dir>` followed by `xark prove <crate-dir> --inputs '{…}'` takes you from source
to a self-verified proof; see [the CLI](/docs/reference/cli).

See [the CLI](/docs/reference/cli) for the full command surface,
[Gadgets](/docs/gadgets) for the crates you can call, and
[the repo's `subset.md`](https://github.com/blueshift-gg/xark/blob/master/docs/subset.md) for the
complete rejection list.
